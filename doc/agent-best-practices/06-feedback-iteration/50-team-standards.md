# 50 最佳实践固化成团队规范

[返回全局摘要](../README.md) · [返回本组：反馈闭环与迭代](README.md)

## Rule
经过验证的 Agent 最佳实践应写入团队规范、模板、检查清单和发布流程，而不是依赖个人经验。

## Why
AI 系统复杂度高，口头经验容易丢失。规范化能让新成员、跨团队协作和长期维护保持一致质量。

Agent 工程不能依赖少数人的临场经验。Prompt 怎么改、工具怎么接、RAG 怎么评测、高风险动作怎么确认、失败怎么归因、灰度怎么放量，都需要进入团队默认流程。否则每个项目都会重新踩一遍同样的问题。

## Optimize
把实践沉淀到 PR checklist、eval 模板、prompt 规范、工具接入标准、发布门禁和事故复盘模板中。

建议沉淀为几类标准件：

| 标准件 | 内容 |
| --- | --- |
| Prompt 模板 | 成功标准、退出路径、输出 schema、示例规范 |
| Tool 接入规范 | schema、权限、错误返回、确认、幂等、审计 |
| RAG 规范 | chunk、元数据、引用、空检索、防注入、可观测 |
| Eval 模板 | 场景标签、风险等级、过程断言、judge rubric |
| 发布门禁 | 回归、灰度、指标、回滚和负责人 |
| 复盘模板 | trace、根因、修复、回归、规范更新 |

规范要和实际工具链绑定。例如 PR checklist 里直接要求填写 Prompt 版本、eval 结果、风险等级和回滚方式；工具接入模板直接要求提供 schema、错误类型和确认策略。

## Engineering Notes

- 规范要短而可执行，不要变成长篇理念文档。
- 规范要随失败更新。每次 P0/P1 问题都应问：是否需要更新模板或门禁。
- 规范要进入代码评审和发布流程，否则没人会稳定遵守。
- 不同风险等级使用不同强度的规范，避免低风险任务负担过重。
- 团队标准要有 owner，定期清理过期内容。

## Verify
定期检查新项目和变更是否引用这些规范，并根据真实失败更新规范内容。

还应检查：

- PR 是否附带必要 eval 和 trace。
- 新工具是否通过接入规范。
- 高风险能力是否有发布门禁。
- 事故复盘是否产生了规范更新。
- 新成员是否能按模板完成一个 Agent 变更。
