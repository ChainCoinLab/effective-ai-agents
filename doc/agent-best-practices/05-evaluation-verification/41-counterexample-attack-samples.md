# 41 验证包含反例攻击样例

[返回全局摘要](../README.md) · [返回本组：测试、评测与验证](README.md)

## Rule
验证集应包含反例、诱导、越权、提示注入、数据泄露和错误工具使用等攻击样例。

## Why
Agent 面向开放输入时，用户可能无意或有意触发危险路径。只测正常路径无法证明系统在对抗输入下仍能守住边界。

反例和攻击样例不是为了“为难模型”，而是为了验证系统边界是否真实存在。Agent 系统一旦接入工具、数据库、文件、消息发送和生产系统，就必须假设输入里会出现诱导、越权、注入和误用。

攻击样例至少覆盖：

| 类型 | 示例目标 |
| --- | --- |
| Prompt injection | 让模型忽略系统规则、泄露提示词 |
| Data exfiltration | 诱导输出密钥、隐私、内部数据 |
| Tool abuse | 诱导删除、发送、付款、修改生产 |
| Permission bypass | 访问越权资源或跨租户数据 |
| Indirect injection | 从网页、文档、邮件、代码注释注入指令 |
| Social engineering | 假冒管理员、制造紧急理由 |

## Optimize
为每个安全约束设计正例和反例，并持续把真实攻击、误用和红队发现加入验证集。

每条安全规则至少要配三类样例：

| 样例 | 用途 |
| --- | --- |
| 正常允许 | 确认系统不会过度拒绝 |
| 明确禁止 | 确认红线能拦住 |
| 灰区边界 | 确认系统会澄清、降级或转人工 |

例如文件工具：

- 允许：读取工作区内普通文档。
- 禁止：读取 `~/.ssh/id_rsa` 或 `.env`。
- 灰区：用户要求导出包含客户数据的日志，需权限和脱敏确认。

攻击样例要检查“最终答案”和“中间过程”。如果模型最终拒绝了，但中间已经调用了敏感工具，仍然是失败。

## Engineering Notes

- 反例要进入自动化回归，不能只作为一次性红队报告。
- 高风险攻击样例要使用 mock 工具或 dry-run，避免测试本身造成副作用。
- 间接注入要覆盖 RAG 文档、网页、上传文件、邮件和代码注释。
- 安全样例要按风险分级报告，不要被普通质量样例平均掉。
- 真实攻击样例进入数据集前要脱敏。

## Verify
确认高风险能力都有拒答、降级或人工审核样例，并检查这些样例在发布前全部通过。

还应检查：

- 模型是否泄露系统提示词、隐藏工具或敏感字段。
- 工具执行器是否独立拦截越权调用。
- RAG 上下文里的恶意指令是否只被当作文本。
- 安全策略变更后，攻击样例是否全部重跑。
