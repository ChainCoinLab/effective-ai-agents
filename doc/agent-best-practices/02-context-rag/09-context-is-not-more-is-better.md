# 上下文不是越多越好

[返回全局摘要](../README.md) · [返回本组：上下文工程与 RAG](README.md)


## Rule
只放入完成当前任务所需的上下文，避免把大量低相关内容塞给模型。Skill、工具说明和 few-shot 示例也属于上下文，不应默认全量注入。

## Why
过多上下文会稀释关键信息，增加成本、延迟和错误引用概率。

当系统有很多 Skill 时，全量注入 Skill 说明会出现和长文档一样的问题。大规模实现见 [大规模 Skill 工程实现](../04-tools-agents/large-scale-skill-engineering.md)。

## Optimize
- 按任务目标筛选上下文。
- 为每段上下文保留来源和相关性理由。
- 设置最大 token、最大文档数和最低相关度阈值。
- 对 Skill、工具说明和示例设置注入预算，只放入与当前任务相关的片段。

## Verify
- 比较不同上下文规模下的准确率和延迟。
- 检查错误答案是否来自低相关上下文。
- 监控上下文命中率和使用率。
- 对比全量上下文和按需上下文的 token 成本、延迟和错误率。
