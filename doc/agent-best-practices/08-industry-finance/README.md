# 金融行业理解

[返回全局摘要](../README.md)

我理解金融行业，不能只把它看成“钱的生意”。金融的核心是围绕资金、风险、信用、时间和信任建立一套可运行的社会协作系统。银行、证券、保险、支付、资管、交易所、清算机构这些角色不同，但底层都在处理三个问题：资金如何流动，风险如何定价，信任如何被制度和系统承载。

## 行业本质

金融行业的产品大多不是实物，而是围绕未来收益、风险承担和信用承诺建立的合约。它天然具有几个特点：

- 高杠杆：小的判断错误可能放大成系统性损失。
- 高监管：金融系统连接公众资产和社会信用，不能只按互联网产品的增长逻辑设计。
- 高数据密度：交易、账户、授信、风控、审计、合规都依赖大量结构化和非结构化数据。
- 高信任成本：用户信任来自安全性、可解释性、连续性和责任边界。
- 高流程复杂度：很多业务不是单点决策，而是跨角色、跨系统、跨规则的流程协作。

所以金融科技的关键不是“把流程线上化”这么简单，而是把风险、合规、效率和用户体验放在同一个系统里平衡。

## 关键知识框架

| 方向 | 需要理解的问题 |
| --- | --- |
| 资产与负债 | 钱从哪里来，投向哪里，期限和收益如何匹配 |
| 信用与风控 | 如何判断一个主体未来能否履约，风险如何度量和控制 |
| 市场与交易 | 价格如何形成，流动性如何影响成交和风险 |
| 支付与清算 | 资金如何转移，账务如何确认，异常如何处理 |
| 合规与审计 | 规则如何进入业务流程，操作如何被追溯和复核 |
| 客户与渠道 | 金融产品如何被理解、比较、购买和持续服务 |

金融系统里最重要的不是单个算法，而是决策链路。一个授信、交易、理赔或合规判断，通常都需要数据来源、规则依据、模型结果、人工复核、审批记录和后续追踪共同构成闭环。

## AI 在金融里的位置

AI 对金融行业有价值，是因为金融天然存在大量知识密集、流程密集、文本密集和决策密集场景：

- 投研和资讯分析：从公告、研报、新闻、财报和市场数据中提取结构化观点。
- 风控辅助：识别异常模式、补充风险解释、生成核查线索。
- 合规审查：对合同、营销材料、交易行为和内部流程做规则匹配。
- 客服与运营：把复杂产品、账户问题和流程状态解释给用户。
- 内部知识库：让制度、流程、产品说明、历史案例可检索、可引用、可追踪。
- 自动化流程：用 Agent 串联查询、比对、生成、复核和归档。

但金融场景不能把 AI 当成最终责任主体。模型可以辅助理解、生成建议、提取线索和组织材料，但权限、审批、风控阈值、交易执行和合规责任必须留在确定性系统和组织流程里。

## 我关注的工程边界

金融 AI 系统最容易出问题的地方，不是模型不够“聪明”，而是边界不清：

- RAG 必须能给出处，不能只给流畅结论。
- Agent 调工具必须有权限、审计和高风险确认。
- 模型输出不能直接变成交易、授信、理赔或合规结论。
- 敏感信息不能默认进入长期记忆。
- 评测不能只测回答质量，还要测引用、合规、越权和拒答。
- 线上反馈要区分事实错误、规则错误、权限错误和流程错误。

所以我会把金融 AI 理解为一类“高约束 AI 工程”：它需要模型能力，但更需要数据治理、权限系统、审计链路、业务规则和人机协同。
