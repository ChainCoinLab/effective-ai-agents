# 拆分 Prompt

[返回全局摘要](../README.md) · [返回本组：提示词与指令](README.md)


## Rule
将复杂任务拆成职责清晰的多个 Prompt 或多个步骤，而不是塞进一个超长 Prompt；同时明确 Prompt 只是在当前上下文中引导工作记忆，不负责改写模型的长期知识或参数。

## Why
单个 Prompt 承担过多职责时，调试困难，错误来源不清，部分修改也容易影响全局行为。

Prompt 的作用位置是当前输入序列、注意力分布和上下文装配结果。它可以激发模型已有能力、注入任务上下文、约束输出格式，但不会让模型在新会话中天然记住新资料，也不会长期改变模型权重。把“当前上下文引导”和“长期能力改造”混在一起，会导致错误的工程选型。

| 目标 | 不合适的做法 | 更合适的做法 |
| --- | --- | --- |
| 激发已有能力 | 堆更长角色设定 | 清晰 Prompt、少量高质量示例、明确输出约束 |
| 回答新知识 | 让 Prompt 逼模型记住资料 | 用 RAG、数据库或工具把证据注入上下文 |
| 长期改变行为 | 期望系统提示词永久改变模型 | 评估微调、偏好优化、规则系统或产品流程 |
| 控制高风险动作 | 只靠自然语言警告 | 用权限、审批、审计和回滚兜底 |

## Optimize
- 按意图识别、检索、推理、生成、校验拆分。
- 为每段 Prompt 定义输入输出契约。
- 只在需要全局一致性时保留共享规则。
- 在 Prompt 设计文档中标明它是在激发已有能力、注入任务上下文、约束输出，还是在承担不该由 Prompt 承担的长期知识或权限控制。
- 把“已有能力激发”和“新知识访问”分开设计：前者用 Prompt 和示例，后者用 RAG、工具或数据库。
- 对高风险行为，不依赖 Prompt 自律；用确定性权限、人工确认、审计和回滚机制控制。

## Verify
- 单独评测每个 Prompt 的结果。
- 检查步骤之间的数据传递是否完整。
- 对端到端链路运行回归测试。
- 在新会话中重复测试，确认所谓“角色认知变化”没有被误判为长期记忆。
- 对比 Prompt、RAG、微调三类方案，分别记录准确率、可追溯性、更新成本和回归风险。
