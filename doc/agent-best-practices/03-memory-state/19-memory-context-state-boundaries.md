## Status
Recommended

Category: memory-state

## Rule
区分短期上下文、长期记忆、结构化记忆和业务状态，不把它们混用。长时间运行的 Agent 应使用分层记忆架构，而不是依赖单一上下文窗口保存全部历史。

## Why
短期上下文服务当前对话，长期记忆服务跨会话偏好，业务状态服务产品事实。混用会导致过期信息、隐私风险和不可预测行为。

Context Window 是当前推理工作区，不是可靠的长期记忆。Agent 运行越久，用户输入、工具结果、错误日志、计划变更和中间结论会持续累积。如果全部追加进上下文，会带来 token 成本上升、关键信息被稀释、旧信息和新信息冲突、摘要丢失细节、任务恢复不可靠等问题。

## Optimize
为三类数据定义独立存储、生命周期和读写入口。业务状态优先来自权威系统，长期记忆只存稳定偏好和用户明确希望保留的信息。

对长时间运行的 Agent，按用途分层：

| 层级 | 保存内容 | 典型实现 | 主要用途 |
| --- | --- | --- | --- |
| 滑动窗口 | 最近几轮用户输入、模型回复、工具观察 | 最近 N 轮消息或 token budget | 保持当前任务的新鲜上下文 |
| 运行摘要 | 被挤出窗口的目标、决策、约束、开放问题 | 递归摘要、会话摘要 | 保留主线，降低 token |
| 长期语义记忆 | 用户偏好、项目事实、历史决策、可复用经验 | 向量数据库、关键词索引 | 按需检索相关旧信息 |
| 结构化记忆 | 实体、关系、计划、负责人、依赖 | 知识图谱、关系表 | 精确处理关系和冲突 |
| 确定性状态 | 任务进度、审批状态、工具结果、重试次数 | 数据库、状态机、队列、工作流引擎 | 支持恢复、审计和幂等 |

每轮结束时，新增信息先分类：临时噪声丢弃或仅进 trace，近期对话留在滑动窗口，目标和约束更新运行摘要，稳定事实按写入规则进入长期记忆，实体关系进入结构化记忆，任务进度和工具结果进入确定性状态系统。

组装上下文时按优先级读取，不要把所有记忆全部注入 Prompt：

```text
稳定规则: 系统指令、权限边界、输出格式
任务状态: 当前进度、待处理项、阻塞点
运行摘要: 目标、关键决策、约束、开放问题
检索记忆: 与本轮输入相关的长期事实和历史证据
滑动窗口: 最近 N 轮对话和工具观察
最新输入: 用户本轮请求
```

摘要适合保留任务主线，但不适合保存所有细节。被摘要压缩掉的原始证据，应通过索引或向量库保留可回查路径。

## Verify
检查同一条信息是否能回答：来源在哪里、何时失效、由谁更新、是否允许跨会话使用。

回放长会话，检查 token、延迟和缓存命中率是否受控；压缩后目标、约束、关键决策和开放问题是否保留；很久以前的具体细节是否能通过检索找回证据；中断恢复是否从状态系统继续；冲突记忆是否能依据来源和时间解释选择。
