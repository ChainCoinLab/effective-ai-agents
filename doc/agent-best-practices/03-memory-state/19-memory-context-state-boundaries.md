# 19. 长任务的记忆管理方式

[返回全局摘要](../README.md) · [返回本组：记忆与状态管理](README.md)

## Status
Recommended

Category: memory-state

## Rule
长任务或长时间运行的 Agent 要分层管理记忆，不应把历史消息、工具结果、错误日志和中间结论无限追加到上下文窗口里。

![状态、记忆和上下文边界](../assets/diagrams/agent-state-memory-boundaries.svg)

## Goals
长任务记忆管理要达到几个目标：

| 目标 | 含义 |
| --- | --- |
| 保持上下文鲜活 | 当前上下文优先包含最新目标、最新约束、最新工具观察和最新用户纠正 |
| 控制成本和延迟 | 历史信息增长不能让每轮 token、响应时间和缓存失效率持续恶化 |
| 精准搜索旧记忆 | 很早以前的偏好、事实、决策和证据，仍能按语义、关键词、实体或时间快速找回 |
| 保留细节证据 | 摘要可以压缩主线，但原始工具参数、引用来源和失败原因要能追溯 |
| 支持中断恢复 | 任务进度、审批状态、重试次数和幂等结果应由确定性状态系统恢复 |
| 允许治理和修正 | 记忆要能更新、删除、标记过期，并避免默认保存敏感信息 |

## Why
上下文窗口是有限预算。即使窗口做到 1M、3000K token 级别，也仍然有上限；窗口越大，输入成本、延迟、缓存和注意力分配问题也越明显。

多轮对话看起来像模型记住了历史，但工程上通常是应用在每一轮请求时，把系统指令、历史消息、工具结果、外部记忆和最新用户输入重新组装后发给大模型。也就是说，历史不是免费存在模型脑子里，而是在每轮调用中重新占用上下文窗口。

Context Window 通常由几类内容拼出来：

| 内容 | 特点 |
| --- | --- |
| 静态提示词 | system prompt、开发者指令、角色、权限边界、输出格式等，通常长期稳定 |
| 会话历史 | 最近多轮用户输入、模型回复、工具观察，随对话增长 |
| 历史摘要 | 被挤出窗口的旧对话压缩成阶段摘要或递归摘要 |
| 外部记忆 | 从向量库、知识库、结构化记忆中检索出的相关片段 |
| 确定性状态 | 任务进度、审批状态、工具结果、阻塞点等 |
| 用户新输入 | 本轮最新请求，通常优先级最高 |

长任务会持续产生新信息：用户补充、模型计划、工具观察、失败重试、临时判断、阶段性结论、外部证据和任务状态。如果没有记忆管理，这些信息会混在同一段自然语言历史里，系统会越来越难控制。

常见问题包括：

| 问题 | 表现 | 影响 |
| --- | --- | --- |
| 上下文窗口有上限 | 历史记录、工具结果和外部记忆不断挤占有限窗口 | 到达上限后必须截断、摘要或丢弃信息 |
| 上下文越来越长 | 每轮都携带更多历史消息和工具结果 | token 成本、延迟和缓存失效率上升 |
| 关键信息被稀释 | 目标、约束、最新决策埋在大量旧消息中 | 模型忽略真正重要的信息 |
| 细节被摘要丢弃 | 压缩时只保留主线，丢掉原始证据或参数 | 后续无法解释、复核或恢复 |
| 旧信息污染新判断 | 过期计划、错误结论和用户纠正前的信息仍在上下文里 | 回答基于旧事实，出现冲突行为 |
| 任务状态不可靠 | 进度、审批、重试次数只写在聊天历史里 | 中断后靠模型猜测，容易重复或漏步骤 |
| 记忆边界混乱 | 偏好、事实、流程状态和临时噪声混在一起 | 隐私、过期和可删除性难以治理 |

更大的上下文窗口只能延后问题，不能替代记忆架构。工程目标不是让模型一次看到全部历史，而是让系统每轮只装配当前任务真正需要的信息，并保留可回查、可更新、可恢复的记忆和状态。

## Avoid
下面这些做法看起来简单，但不适合作为长任务记忆方案：

| 做法 | 为什么不好 |
| --- | --- |
| 全量追加历史 | 成本持续上涨，旧噪声持续污染上下文，窗口迟早溢出 |
| 只依赖超长上下文 | 关键信息仍可能迷失在中间，且成本和延迟不可控 |
| 只保留滚动摘要 | 摘要能保主线，但会丢失细节证据、工具参数和原始来源 |
| 把所有记忆都注入 Prompt | 相关性低的信息会干扰当前任务，也增加隐私和注入风险 |
| 让模型自由写记忆 | 容易写入临时判断、敏感信息、重复事实或未经确认的偏好 |
| 用自然语言历史当状态机 | 任务恢复、审批、幂等和审计都不可靠 |

## Optimize
核心思路是分层管理：Context Window 只是本轮 Prompt 的有限组装区，不是长期记忆层。不同类型的信息进入不同层，再按任务需要检索、压缩和装配。

| 层级 | 目标 | 保存内容 | 所用手段 | 读取方式 |
| --- | --- | --- | --- | --- |
| Context Window | 让模型完成本轮推理 | 静态提示词、会话历史、历史摘要、当前状态、检索片段、滑动窗口、用户新输入 | Prompt 组装、优先级排序、token budget | 每轮重新组装，只放当前最需要的信息 |
| 短期上下文管理 | 保持上下文鲜活，同时保留被挤出窗口的任务主线 | 最近几轮用户输入、模型回复、工具观察；旧对话中的目标、约束、决策、开放问题 | 滑动窗口、最近 N token 裁剪、阶段摘要、递归摘要、摘要增量更新 | 最近内容默认注入，旧内容以摘要形式注入 |
| 向量数据库 | 快速找回长期语义记忆 | 稳定偏好、项目事实、历史经验、可复用知识、原始证据片段 | embedding、语义检索、关键词混合检索、rerank | 按当前问题检索相关片段，不全量注入 |
| 知识图谱 / 结构化记忆 | 精确处理实体和关系 | 用户、项目、文件、计划、依赖、负责人、版本关系 | 关系表、图数据库、结构化文档、实体抽取 | 按实体、关系或约束精确查询 |
| 确定性状态库 | 支持恢复、审计和幂等 | 任务进度、审批状态、工具结果、重试次数、幂等键 | 数据库、状态机、队列、工作流引擎 | 恢复任务时优先读取 |
| Trace / 原始证据层 | 保留可追溯细节 | 原始工具输入输出、引用来源、失败原因、完整事件流 | trace log、artifact、对象存储、审计日志 | 调试、复核、失败归因时回查 |

分层以后，每一轮只把“需要参与本轮推理的内容”装进 Context Window。旧记忆不应该因为存在就自动进入 Prompt，而应该经过检索、过滤、排序和压缩。

每轮结束后做信息分流：

```text
临时噪声 -> trace 或丢弃
近期对话 -> 短期上下文管理层的滑动窗口
目标 / 约束 / 决策 / 开放问题 -> 短期上下文管理层的运行摘要
稳定事实 / 偏好 / 经验 -> 记忆写入候选
实体 / 关系 / 依赖 -> 结构化记忆
任务进度 / 工具结果 / 审批 -> 确定性状态
```

记忆写入需要应用层规则，不要完全交给模型自由决定。写入前至少判断：

- 是否是稳定事实、明确偏好或可复用经验。
- 是否有来源、时间、置信度和适用范围。
- 是否获得用户授权，是否包含敏感信息。
- 是否可能过期，是否需要失效条件。
- 是否应该进入长期记忆、结构化记忆，还是只进入 trace。

上下文装配时按优先级读取：

```text
稳定规则: 系统指令、权限边界、输出格式
确定性状态: 当前进度、审批状态、阻塞点、工具结果
短期上下文: 最近 N 轮对话和工具观察、目标、关键决策、约束、开放问题
检索记忆: 与本轮输入相关的长期事实和历史证据
最新输入: 用户本轮请求
```

一个实用原则是：摘要保主线，索引保追溯，状态保恢复。摘要不负责保存所有细节；被压缩掉的原始证据，应通过 trace、索引或向量库保留可回查路径。流程进度、审批和幂等结果则应进入确定性状态系统。

长任务每轮可以按下面的流程处理，每一步都要有明确目标和手段：

| 步骤 | 目标 | 所用手段 | 产物 |
| --- | --- | --- | --- |
| 接收新输入 | 把最新用户意图放到最高优先级 | 保留原始输入、提取目标和约束 | 当前请求、候选目标 |
| 读取确定性状态 | 知道任务做到哪里、哪些动作已完成 | 查数据库、状态机、队列、工作流实例 | 当前进度、阻塞点、审批状态 |
| 检索长期记忆 | 找回以前相关事实、偏好和证据 | 向量检索、关键词检索、实体过滤、rerank | 相关记忆片段和来源 |
| 查询结构化记忆 | 精确确认实体、关系和依赖 | 知识图谱、关系表、结构化索引 | 实体关系、版本关系、负责人、依赖 |
| 合并短期上下文 | 同时保留最近对话的新鲜度和旧对话的任务主线 | 滑动窗口、最近 N token 裁剪、阶段摘要、递归摘要 | 最近对话、工具观察、目标、决策、约束、开放问题 |
| 组装 Context Window | 控制有限窗口里的优先级和长度 | Prompt 模板、token budget、去重、排序 | 本轮模型输入 |
| 执行推理和工具调用 | 完成本轮任务推进 | LLM、工具调用、权限检查、错误恢复 | 模型回答、工具结果 |
| 写入 trace | 保留完整可追溯证据 | trace log、artifact、审计日志 | 原始输入输出和事件流 |
| 更新状态和记忆 | 让系统能恢复、检索和持续改进 | 状态写入、摘要更新、记忆写入规则 | 新状态、新摘要、记忆写入候选 |

## Verify
用长会话回放和中断恢复测试校验记忆管理：

- token、延迟和缓存命中率是否随轮次增长仍受控。
- 最新用户纠正、最新目标和最新工具观察是否优先进入当前上下文。
- 压缩后是否保留目标、约束、关键决策和开放问题。
- 很久以前的具体事实是否能通过关键词、语义、实体或时间检索快速找回。
- 被摘要压缩掉的工具参数、引用来源和失败原因是否仍能追溯。
- 每条注入上下文的长期记忆是否能说明来源、时间、置信度和适用范围。
- 用户纠正旧记忆后，后续回答是否使用新事实。
- 中断重启后，任务是否从确定性状态继续，而不是靠模型猜测。
- 敏感信息是否被默认排除在长期记忆之外。
- 冲突记忆是否能根据来源、时间和置信度解释选择。

## Summary
长任务记忆管理的核心，不是让模型记住所有历史，而是用滑动窗口保持鲜活，用检索记忆精准找回，用递归摘要浓缩精华，并把有限的 Context Window 留给本轮真正需要的信息。
