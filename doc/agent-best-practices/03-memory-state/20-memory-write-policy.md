# 20. 记忆应有写入规则

[返回全局摘要](../README.md) · [返回本组：记忆与状态管理](README.md)

## Status
Recommended

Category: memory-state

## Rule
长期记忆写入应有明确规则，不应把对话内容默认全部保存。

## Why
记忆会影响未来行为。没有写入规则会积累噪声、误解、临时需求和不该保留的信息。

长期记忆一旦被写入，就可能在未来很多任务里影响模型判断。错误记忆会让 Agent 持续使用错误前提；噪声记忆会降低检索质量；敏感记忆会扩大合规风险；临时需求被保存后，会让后续任务出现莫名其妙的偏好。

需要写入规则，是因为对话内容并不等于可保存记忆：

| 对话内容 | 是否适合长期保存 | 原因 |
| --- | --- | --- |
| “这次报告用中文写” | 通常不适合 | 单次任务约束 |
| “以后给我的技术文档默认用中文” | 适合候选 | 稳定偏好 |
| “我现在很着急” | 不适合 | 临时情绪 |
| “项目使用 pnpm，不要用 npm” | 适合候选 | 可复用项目事实 |
| “我的身份证号是...” | 默认不适合 | 敏感信息 |
| “这个 bug 可能是缓存导致” | 不适合直接保存 | 未确认推测 |

## Optimize
只写入稳定、可复用、用户可能希望下次仍生效的信息。写入前判断是否具体、长期有效、与未来任务相关、不会造成隐私或安全问题。

推荐建立写入决策表：

| 判断项 | 通过标准 |
| --- | --- |
| 稳定性 | 不是只适用于当前任务、当前情绪或当前临时条件 |
| 可复用性 | 未来任务读取后能产生明确价值 |
| 明确性 | 表达具体，不是模糊推测或含糊评价 |
| 来源可信 | 来自用户明确陈述、工具观察或已确认事实 |
| 隐私安全 | 不包含默认禁止保存的敏感信息 |
| 可治理 | 能设置来源、时间、作用域、过期条件和删除路径 |

可以把写入分成三类：

```text
auto_write: 低风险、明确、稳定的偏好或项目事实
confirm_before_write: 可能影响较大或涉及个人偏好的信息
never_write: 密钥、凭据、身份证明、健康财务等敏感信息
```

记忆条目应尽量结构化：

```json
{
  "memory_id": "project_pkg_manager_ai_learn",
  "scope": "project:/Users/fcihpy/Desktop/fc/ai-learn",
  "type": "project_preference",
  "content": "该项目使用 pnpm 时应优先遵守 lockfile 和现有脚本。",
  "source": "user_message",
  "created_at": "2026-05-22",
  "confidence": "user_confirmed",
  "ttl": null
}
```

## Engineering Notes

- 写入记忆是产品行为，不是模型自由发挥。模型可以提出写入候选，应用层决定是否保存。
- 记忆要有作用域。用户偏好、项目规则、组织规则和单任务结论不能混在一个全局池里。
- 记忆要去重和合并。重复保存同一偏好会让检索结果膨胀。
- 未确认推测不要写成事实。可以进入 trace 或待确认候选，但不能作为长期记忆影响未来。
- 长期记忆不应替代项目文档、配置文件或业务数据库。

## Verify
抽样审查新记忆，确认它不是一次性任务、临时情绪、推测结论或敏感数据。

还应测试：

- 用户说“这次”时不会写入长期记忆。
- 用户说“以后都”时进入候选或确认流程。
- 模型推测出的结论不会未经确认写入。
- 同一偏好重复出现时会合并或更新，而不是无限追加。
- 敏感信息样例会被拒绝或要求显式确认。
