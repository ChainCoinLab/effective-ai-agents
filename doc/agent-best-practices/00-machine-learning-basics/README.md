# 机器学习与大模型

[返回全局摘要](../README.md)

这一节是理解 AI 的底层入口。大模型、RAG、Agent、工具调用这些能力看起来很新，但底层仍然绕不开机器学习的基本问题：系统如何从数据中学习规律，如何在没见过的输入上泛化，以及如何把训练阶段学到的模式用于推理阶段。

## 从机器学习到大模型

机器学习不是让机器“记住答案”，而是让模型通过数据学习输入和输出之间的规律。这个规律可能是一个线性回归模型，也可能是一个卷积神经网络中的图像特征，还可能是大模型参数里压缩出的语言、知识和任务模式。

传统机器学习、深度学习和大模型可以放在同一条演进线上看：

| 阶段 | 核心方式 | 主要变化 |
| --- | --- | --- |
| 传统机器学习 | 人设计特征，模型学习决策边界 | 重点在特征工程、回归、分类和泛化 |
| CNN | 用卷积提取局部空间特征 | 适合图像、视觉和局部模式识别 |
| RNN | 按时间步处理序列状态 | 适合早期文本、语音、时间序列建模 |
| Transformer | 用注意力机制建模 token 之间的关系 | 更适合并行训练和长距离依赖建模 |
| 大模型 | 用大规模数据和 Transformer 学习通用表示 | 一个模型可以通过上下文适配多种任务 |

这条线索很重要，因为它能解释为什么大模型既强大又有边界：它学到的是分布、关联、模式和生成能力，而不是天然拥有事实数据库、权限系统、业务状态机或执行能力。

## 训练过程里的核心术语

| 概念 | 作用 |
| --- | --- |
| 数据 | 模型学习规律的来源，质量、覆盖范围和噪声会直接影响能力边界 |
| 特征 | 被模型用于判断的表示，传统 ML 依赖人工设计，深度学习更多自动学习 |
| 标签 | 监督学习中的目标信号，决定模型朝什么方向优化 |
| 前向传播 | 输入经过模型参数计算出预测结果 |
| 损失函数 | 把预测结果和目标之间的差距变成可优化的数值 |
| 反向传播 | 根据损失计算参数梯度，决定每个参数应该如何调整 |
| 梯度下降 | 沿着降低损失的方向更新参数 |
| 回归 | 预测连续数值，例如价格、概率、评分或风险分 |
| 分类 | 判断输入属于哪个类别，例如是否违约、是否异常、意图类型 |
| 泛化 | 模型在未见过样本上仍能表现稳定的能力 |
| 过拟合 | 模型记住训练数据细节，却没有学到可迁移规律 |

这些概念决定了后面理解大模型时的很多问题：为什么需要训练数据，为什么模型会幻觉，为什么微调会改变模型行为，为什么评测不能只看几个样例。

## CNN、RNN 和 Transformer 的位置

CNN、RNN、Transformer 不是互相孤立的名词，而是深度学习处理不同结构数据时的代表性架构：

- CNN 强在局部特征提取。卷积核在局部区域滑动，能够捕捉边缘、纹理、局部形状等模式。
- RNN 强在序列状态传递。它把前面的状态带到后面的计算中，但长距离依赖和并行训练效率是明显瓶颈。
- Transformer 强在注意力机制。它直接计算 token 之间的关系，更适合并行训练，也更容易扩展到大规模语言模型。

理解这条演进线，才能理解为什么现代大模型主要建立在 Transformer 之上，也能理解大模型并不是凭空出现的，而是机器学习、深度学习、算力、数据和工程系统共同演进的结果。

## 微调、RAG 和评测

大模型进入具体业务时，常见优化方式包括 Prompt、RAG 和微调。它们解决的问题不同：

- Prompt 更像任务定义，告诉模型当前要做什么、边界在哪里、输出格式是什么。
- RAG 更像外部知识访问，把检索到的证据放入上下文，解决知识更新和事实依据问题。
- 微调更像行为和能力适配，用领域数据继续训练模型，让它更稳定地符合某类任务模式。

评测是大模型工程里不可缺少的一层。没有评测，就很难判断一次 Prompt 修改、一次 RAG 策略调整、一次微调或一次模型升级到底是变好了还是只是样例上看起来更好。评测应该覆盖最终答案，也覆盖检索、引用、格式、工具调用、拒答、越权和失败恢复。

理解这一点之后，再进入 [大模型原理与工程边界](../00-llm-basics/README.md) 会更清楚：Transformer、上下文窗口、Prompt、RAG、Agent 和工具调用，本质上都是围绕“如何使用模型能力，以及如何补齐模型边界”展开的工程设计。
