# Web3 行业理解

[返回全局摘要](../README.md)

我理解 Web3，不能只把它看成币价、交易或一个新的前端形态。Web3 的核心是用密码学、区块链、智能合约和代币机制，把资产、身份、规则和协作关系放到一个开放网络上执行。它和传统互联网最大的差异，不只是技术栈不同，而是信任模型、账户体系、资产形态和组织方式都发生了变化。

## 行业本质

传统互联网更多是平台托管数据、账户和交易规则。Web3 更强调用户自己持有密钥，链上状态公开可验证，规则通过智能合约执行，价值通过 token 或链上资产流转。

这带来几个核心特征：

- 开放性：链上数据、合约和交易记录天然更容易被读取和组合。
- 可组合性：协议、资产和工具可以像模块一样被其他应用继续调用。
- 自托管：用户直接控制钱包和私钥，同时也直接承担操作风险。
- 规则代码化：智能合约把部分业务规则变成可执行代码。
- 激励机制显性化：token 把参与、治理、收益和风险绑定在一起。

Web3 的难点也来自这些特征：开放带来攻击面，可组合带来传导风险，自托管提高用户门槛，代码化规则要求极高的安全性，token 激励容易放大短期行为。

## 关键知识框架

| 方向 | 需要理解的问题 |
| --- | --- |
| 区块链账本 | 状态如何被记录、同步、确认和回滚风险如何处理 |
| 钱包与账户 | 私钥、地址、签名、授权和资产控制权如何工作 |
| 智能合约 | 规则如何被代码化，合约如何升级、调用和审计 |
| Token 机制 | 资产、激励、治理和流动性如何被设计 |
| DeFi | 交易、借贷、做市、清算和预言机如何形成金融协议 |
| 安全与风控 | 合约漏洞、私钥泄露、钓鱼授权、流动性攻击如何防范 |
| 社区与治理 | 协议如何决策，参与者如何协调，激励如何影响治理 |

Web3 不是单纯的“去中心化应用开发”，而是一套技术、金融、治理和安全交织在一起的系统。

## AI 在 Web3 里的位置

AI 和 Web3 的结合点，不应该停留在概念叠加。更实际的方向是让 AI 帮助用户和开发者理解复杂链上系统、降低操作门槛、提升风控和自动化能力：

- 链上数据分析：解释地址行为、资金流向、协议交互和异常模式。
- 智能合约理解：辅助阅读合约、总结权限、识别高风险函数和外部依赖。
- 安全审计辅助：生成测试思路、发现常见漏洞模式、补充审计 checklist。
- 交易与资产解释：把复杂的 DeFi 仓位、收益来源和清算风险解释清楚。
- 钱包操作辅助：帮助用户理解签名请求、授权范围和潜在风险。
- 协议运营 Agent：自动监控数据、生成报告、触发告警和整理治理材料。

但 Web3 场景的 AI 不能越过安全边界。任何涉及签名、转账、授权、合约部署、治理投票和交易执行的动作，都必须有明确权限、可解释预览和人工确认。

## 我关注的工程边界

Web3 AI 系统的风险很直接：一次错误授权、一次错误签名、一个错误合约地址，就可能造成不可逆损失。因此工程上必须强调：

- 私钥绝不交给模型，也不进入上下文。
- 模型只能解释签名意图，不能绕过用户确认。
- 合约和地址必须有来源、链 ID 和校验信息。
- Agent 调用链上工具时要区分模拟、查询、构造交易和真正广播交易。
- 高风险动作需要分级确认和审计记录。
- 对链上数据的解释要保留证据链接和交易哈希。

Web3 比很多行业更能体现“模型只提出意图，应用负责权限”的原则。模型可以成为理解和编排层，但不能成为资产安全边界。
