# 00.10 状态管理基础

[返回全局摘要](../README.md) · [返回本组：AI 工程基础知识与原理](README.md)

状态管理解决的是任务流程的确定性记录问题。Agent 可以生成计划和判断下一步，但任务是否完成、审批是否通过、工具是否成功，不应该只靠模型在对话里“记得”。

## 状态解决什么问题

状态管理用于记录：

- 当前任务进行到哪一步。
- 哪些子任务已完成、失败或待处理。
- 哪些工具调用已经执行。
- 哪些结果已经被验证。
- 哪些动作等待人工审批。
- 是否可以恢复、重试或结单。

## 状态和上下文的区别

| 概念 | 作用 |
| --- | --- |
| 上下文 | 本轮传给模型的信息 |
| 记忆 | 可复用的长期事实和偏好 |
| 状态 | 确定性的任务进度和系统事实 |

状态可以被摘要后放进上下文，但状态本身应由数据库、工作流引擎、任务表或其他确定性系统保存。

## 常见状态字段

```json
{
  "task_id": "task_123",
  "goal": "生成客户投诉分析报告",
  "status": "running",
  "current_step": "retrieve_policy",
  "completed_steps": ["parse_input", "fetch_customer_record"],
  "pending_approvals": [],
  "tool_calls": [],
  "evidence_refs": [],
  "risk_level": "medium"
}
```

## 工程原则

- 状态变化要可追踪。
- 高风险动作要幂等，避免重复执行。
- 失败后能从最近检查点恢复。
- 状态更新应由应用控制，不由模型自由决定。
- 最终结单要包含完成范围、失败项和剩余风险。
