# 00.1 大模型的发展历史

[返回本章](README.md)

这一节解释大模型的发展脉络：从早期统计语言模型，到 CNN、RNN、Attention，再到现代大语言模型普遍采用的 Transformer。

![大模型结构演进](../assets/diagrams/model-evolution.svg)

## 1. 统计语言模型：从规则到概率

早期自然语言处理大量依赖人工规则、词典、模板和统计方法。n-gram 语言模型会根据前面几个词预测下一个词，例如根据 `我 想 吃` 预测后面更可能出现 `饭`、`苹果` 或 `面条`。

这类方法已经有“概率预测”的雏形，但上下文窗口很短，无法真正理解长距离依赖、语义关系和复杂任务。

## 2. CNN：擅长局部特征

卷积神经网络（CNN）最早在图像任务中非常成功。它的核心特征是：

- **局部感受野**：一次看局部区域，例如图像中的边缘、纹理、角点，或文本中的局部词组。
- **参数共享**：同一个卷积核在不同位置重复使用，减少参数量，也能识别不同位置出现的相似模式。
- **平移等变性**：特征出现在左上角还是右下角，模型都能用相似方式识别。
- **并行计算友好**：不同位置的卷积可以并行处理。

CNN 用在文本上时，可以很好捕捉局部模式，比如短语、关键词组合、局部句法特征。但它天然不擅长处理很长的依赖关系。要让 CNN 理解远距离信息，通常需要堆很多层、扩大卷积核、使用 dilation 或额外机制。

因此，CNN 更像“局部特征提取器”，不是今天大语言模型的主干结构。

## 3. RNN / LSTM / GRU：按顺序读文本

循环神经网络（RNN）更贴近语言的顺序结构。它会从左到右读 token，把前面的信息压缩进一个隐藏状态，再用这个状态处理下一个 token。

它的直觉很自然：

```text
前面的词 -> 隐藏状态 -> 当前词 -> 新隐藏状态 -> 下一个词
```

LSTM 和 GRU 在 RNN 基础上加入门控机制，用来缓解长期信息丢失问题。它们可以选择记住、遗忘或更新部分状态。

RNN 系列的问题也很明显：

- 计算必须按顺序进行，难以充分并行。
- 长文本的信息会被压缩进有限状态，远距离依赖容易丢失。
- 训练长序列时容易出现梯度消失或梯度爆炸。
- 对复杂上下文的表达能力受限。

RNN 让模型从“看局部”前进到“读序列”，但还不足以支撑今天的大规模预训练和长上下文推理。

## 4. Attention：让模型直接看相关位置

Attention 的关键变化是：模型不再只依赖一个被压缩的隐藏状态，而是可以在生成或理解某个 token 时，直接关注输入中更相关的位置。

例如翻译一句话时，生成目标词不一定只看源句最后一个状态，而是可以对源句中每个词分配不同权重。

这解决了长距离依赖的一部分问题，也为 Transformer 铺路。

## 5. Transformer：用自注意力建模全局关系

Transformer 的核心是 self-attention。它让序列中的每个 token 都可以和其他 token 建立关系，并计算“我现在应该关注谁”。

一个简化的过程是：

1. 把文本切成 token。
2. 把 token 转成向量，也加入位置信息。
3. 对每个 token 计算 Query、Key、Value。
4. 用 Query 和其他 token 的 Key 计算相关性权重。
5. 按权重汇总 Value，得到带上下文的新表示。
6. 多层堆叠后，输出下一个 token 的概率分布。

Transformer 的优势是：

- **并行训练**：不像 RNN 必须一步步读，训练效率更适合大规模数据。
- **全局依赖**：每个 token 可以直接关注上下文中的其他 token。
- **可扩展性强**：模型参数、数据量和算力扩大后，能力持续提升。
- **适合预训练**：可以先在海量数据上学习语言、知识、代码和模式，再用指令微调、人类反馈和工具系统适配任务。

今天的大语言模型基本建立在 Transformer 或其变体之上。
