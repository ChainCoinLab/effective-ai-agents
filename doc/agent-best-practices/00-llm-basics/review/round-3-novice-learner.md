# Round 3 小白学习者复审：大模型基础 01-16

## 总判断

从初学者角度看，Round 2 合并修订已经解决了小白复审提出的主要问题。当前版本不再只是“逻辑上能读通”，而是更明确地告诉第一次阅读的人：先按什么阶段读、遇到工程词先怎么理解、长章节先抓哪三件事。

这轮最有效的改动有四类：

- `README.md` 增加阶段速览，把 01-16 分成地图、机器学习基础、表示与架构、训练/推理/评测/边界，降低了“16 节一长串”的压力。
- `SUMMARY.md` 也按阶段分组，目录页比 Round 2 前更容易扫描。
- 08、09、10、13、14、15 的章首都增加了“第一次读，本节先带走三件事”，能让小白先抓最低掌握线。
- 第 15 节回扣第 06 节评估概念，第 16 节把 MCP 图移到“为什么需要 Agent”处，并说明第一次读不用理解协议细节。

因此，本轮不需要继续从小白学习路径角度发起新的大规模修订。

## Round 2 主要问题解决情况

### 已解决：长章节缺少首次阅读抓手

定位：

- `03-token-and-embedding.md`
- `04-next-token-prediction.md`
- `05-capability-from-prediction.md`
- `09-training-and-alignment.md`
- `10-inference-and-parameters.md`
- `12-evaluation.md`

这些章节新增的“第一次读，本节先带走三件事”是有效的。它没有压缩正文，但先把读者要抓住的判断放在前面，能缓解“读到中途不知道哪句最重要”的问题。

对小白来说尤其有帮助的是：08 节明确区分 token id 和 embedding，09 节明确输出是概率分布，10 节明确能力来源不等于产品可靠性，13 节明确结构、训练阶段和推理阶段不是一类东西，14 节明确参数不能增加事实知识，15 节明确评测不是看一次回答好不好。

### 已解决：MCP 在入口处缺少一句话解释

定位：`README.md` 的“阅读约定”。

现在 MCP 被解释为“工具和模型之间的标准化连接方式，先理解成让 Agent 统一发现和调用外部能力”。这对第一次读足够了。读者不需要提前理解协议、server、client、transport 等实现细节，也能知道 MCP 为什么会出现在工具调用和 Agent 路线里。

### 已解决：SUMMARY 阶段分组不足

定位：`SUMMARY.md`。

现在“大模型基础与工程边界”下按“机器学习基础”“表示与架构”“训练、推理、评测和边界”分组，比 01-16 平铺更适合初学者扫描。它也和 `README.md` 的阶段速览一致，没有制造新的路径冲突。

### 已解决：第 15 节和第 06 节评估概念关系不够清楚

定位：`12-evaluation.md` 开头。

现在第 15 节明确说明：第 06 节的训练集、验证集、测试集是为了避免模型只适配训练数据；第 15 节把同一思想放到大模型应用里，评测对象扩展到 prompt、RAG、工具链、生成参数、成本、延迟和安全边界。

“Golden dataset 可以先理解成大模型应用里的固定测试集”这句话对小白很关键，能把旧概念接到新场景上。

### 已解决：第 16 节 MCP 图章首压力

定位：`16-llm-capabilities-boundaries.md` 的“为什么需要 Agent”。

MCP 图已经不再压在第 16 节开头，而是放到“为什么需要 Agent”处。图后说明也明确要求第一次读只看三件事：模型提出调用意图、工具层执行真实动作、执行结果回到上下文。

这比 Round 2 前更符合小白阅读节奏：先理解大模型边界，再看为什么需要工具和 Agent，而不是一进章节就被 MCP 协议图打断。

## 后续建议

- 长章节正文仍然偏长，但已经有最低掌握线。后续可以继续做“进阶阅读 / 工程备查”标记，不必作为当前轮次阻塞项。
- 文件名编号和正式章节编号仍不一致，但 `README.md` 和 `SUMMARY.md` 已经明确以正式顺序为准。这个更像维护问题，不是当前小白阅读阻塞。
