# 小白学习者审查反馈

## 总体学习感受

我按 README 里的 01 到 16 顺序读完后，感觉这套章节的主线是有的：先讲机器学习怎么学，再讲 token、embedding、next-token、Attention、Transformer、训练、推理、评测，最后收束到大模型边界和 Agent。作为没有大模型基础的人，我能明白作者想让我建立一个判断：大模型不是万能后端，而是一个基于上下文预测 token 的概率生成组件。

但我不能完全顺畅地从 01 一路读到 16。前 01-10 节整体比较好懂，例子多，链路也比较清楚。明显卡住主要出现在三类地方：

- 有些章节的“连接到下一节”和实际顺序不一致，会让我怀疑自己是不是读错文件。
- 11-14 节开始公式、英文缩写、工程术语突然变多，我能看懂直觉类比，但中间机制会断。
- 每节固定 4 张图有时不是加深理解，而是在开头提前塞入后面章节的图，反而让我带着没解释过的概念往下读。

最后“为什么需要 Agent”的方向是自然的，因为前面一直在讲模型不能负责事实、权限、状态、执行和评测。但第 16 节如果想让小白真正进入 Agent，最好再加一个贯穿小例子，把“模型、RAG、工具、状态、权限、评测”各自做什么串起来。现在结论是对的，但我还缺一个能落地想象的故事。

## P0：严重断层

### P0-1

- 章节名：02. 从函数到机器学习
- 具体位置/小标题：连接到下一节
- 我卡住的点：这里说“接下来要讲：现实对象如何变成特征向量”，但 README 里的下一节其实是“03. 从线性模型到神经网络”。我读完后翻到下一篇，发现不是向量，而是神经网络，会以为自己打开错文件。
- 建议怎么补：把这里改成先承接神经网络，例如“下一节先看为什么简单线性函数不够，需要神经网络；再往后回到输入端，讲现实对象如何向量化。”如果原本想让向量在神经网络前讲，也需要同步调整 README 顺序。

### P0-2

- 章节名：11. 从上下文问题到 Attention
- 具体位置/小标题：相关性分数怎么工作
- 我卡住的点：Q/K/V 的类比我能懂，但公式 `Attention(Q, K, V) = softmax(QK^T / sqrt(d)) V` 突然变难。前面只见过 `W*x+b`，这里突然出现转置、矩阵相乘、`sqrt(d)`、softmax 权重矩阵。我能背下“Q 找 K，取 V”，但不知道这一步到底怎么从几个 token 算出来。
- 建议怎么补：加一个只有 3 个 token 的极小例子，不用真实大矩阵，只展示“当前 token 的 Q 分别和 3 个 K 打分 -> softmax 变成 0.7/0.2/0.1 -> 按权重混合 3 个 V”。`sqrt(d)` 可以只说“防止分数太大，让 softmax 不要一下子极端化”，不用展开数学证明。

### P0-3

- 章节名：16. 大模型能做什么，不能做什么
- 具体位置/小标题：为什么需要 Agent
- 我卡住的点：前面铺垫了模型边界，所以“需要 Agent”这个结论我认同。但到了 Agent 闭环时，突然出现感知、规划、行动、观察、校验、workflow、状态、权限、trace、MCP 等工程词。我知道它们很重要，但还没看到一个完整任务里这些东西怎么分工。
- 建议怎么补：在“为什么需要 Agent”前先加一个最小故事，例如“用户要根据公司制度判断能不能报销并提交申请”：模型理解问题，RAG 找制度，工具查额度，权限系统判断用户身份，状态系统记录申请进度，评测/日志记录结果。用这个例子把 Agent 闭环跑一遍，再进入表格。

## P1：明显影响理解

### P1-1

- 章节名：01. 大模型发展历史
- 具体位置/小标题：总览路线
- 我卡住的点：第一节一上来就出现 RNN、LSTM、Seq2Seq、Attention、Transformer、BERT、GPT、Instruction Tuning、RLHF、DPO、Agent。作为小白，我知道这是地图，但名词太密，会有“我是不是应该已经懂这些”的压力。
- 建议怎么补：在总览路线前加一句“这些名词现在不用懂，只要先看它们解决了什么问题，后面会逐个拆开”。也可以加一个“小白版词汇表”，每个词只给一句话。

### P1-2

- 章节名：04. 前向传播、损失函数与反向传播
- 具体位置/小标题：从哪里来：预测本身不会自动带来学习
- 我卡住的点：链式法则、导数、`d loss / d w` 一出现，难度明显上升。虽然有考试类比，但我还缺一个“不懂微积分也能看懂”的过渡。
- 建议怎么补：先用一个参数的小例子说清楚“把 w 调大一点，loss 变大还是变小”，再说这就是导数/梯度想回答的问题。公式可以保留，但先让读者知道公式在问什么。

### P1-3

- 章节名：05. 梯度下降与模型训练
- 具体位置/小标题：optimizer 不只是普通梯度下降、工程层：训练日志怎么看
- 我卡住的点：SGD、Momentum、Adam、一阶估计、二阶估计、grad norm、warmup、decay、梯度裁剪一起出现，我能知道它们都是训练技巧，但分不清哪些是必须先懂，哪些只是以后调参再懂。
- 建议怎么补：加一个“初学者先掌握这 4 个就够了”的提示：learning rate、batch、epoch、optimizer。其他高级词放在“先知道名字即可”的框里，避免读者以为都要马上理解。

### P1-4

- 章节名：06. 拟合、泛化与过拟合
- 具体位置/小标题：形式层：泛化差距与评估指标
- 我卡住的点：accuracy、precision、recall、F1、AUC 一口气出现，但没有用一个二分类小例子展开。作为小白，我很容易把 precision 和 recall 混掉。
- 建议怎么补：这里不用讲很多指标。可以只用垃圾邮件例子解释 accuracy、precision、recall，F1/AUC 先标成“进阶指标，后面评测章节再看”。

### P1-5

- 章节名：08. 从文字到 token 和 embedding
- 具体位置/小标题：one-hot 为什么不够、向量空间如何表达相似性
- 我卡住的点：one-hot 的直觉很好，但“点积为 0”“彼此正交”“余弦相似度”会突然让我进入线代模式。我能大概懂“方向相似”，但不确定为什么点积能说明相似。
- 建议怎么补：补一个 2 维或 3 维的小向量图解/表格，例如 `[1,0]` 和 `[0,1]` 完全不重叠，所以点积是 0；`[1,1]` 和 `[1,0.8]` 方向接近，所以更相似。公式之后再出现。

### P1-6

- 章节名：09. 语言模型为什么预测下一个 token
- 具体位置/小标题：语言模型是什么：从上下文到概率分布的函数
- 我卡住的点：logits、softmax、概率分布讲得比较完整，但我还是缺一次真正的“数字怎么变概率”的过程。表格里有 logit 和概率，但没有展示为什么 4.2 会变成 0.60。
- 建议怎么补：加一个“可以不算，只看趋势”的小框：logit 高 -> `exp` 后更大 -> 除以总和后概率更大。再说明真实模型不是只算 4 个候选，而是对整个词表算。

### P1-7

- 章节名：10. 为什么预测下一个 token 会产生能力
- 具体位置/小标题：规模与泛化：为什么模型变大后能力增强
- 我卡住的点：这里说模型变大后能力增强，但“逐步增强”和大家常说的“涌现能力”之间是什么关系没有讲清楚。我会疑惑：能力是突然冒出来的，还是一直慢慢变好？
- 建议怎么补：加一段小白解释：有些能力在指标上看起来像突然跨过门槛，是因为小模型一直没到可用线；但底层仍然来自数据、参数、计算和训练目标共同提升。避免把规模效应理解成魔法。

### P1-8

- 章节名：12. Transformer 如何一步步形成
- 具体位置/小标题：Position embedding、Multi-head attention、FFN、LayerNorm / RMSNorm
- 我卡住的点：这一节主线清楚，但高级名词太密：RoPE、RMSNorm、GELU、SwiGLU、MQA/GQA、MoE、FlashAttention 等不断出现。它们每个都只解释一点点，我读的时候会被带偏，忘了 Transformer block 的主干。
- 建议怎么补：把这些高级变体统一放进“了解即可，不影响本节主线”的提示框。正文先只讲 token embedding、position、attention、FFN、residual、norm、mask 这 7 个核心组件。

### P1-9

- 章节名：13. 预训练、指令微调与对齐
- 具体位置/小标题：reward model、RLHF 与 DPO：从示范答案到偏好优化
- 我卡住的点：SFT 还能理解成“看指令和示范答案继续学”，但 reward model、RLHF、DPO 一下子变复杂。我尤其不懂“强化学习”在这里到底做了什么，只知道是让高分答案概率更高。
- 建议怎么补：先加一个两答案选择例子：同一个 prompt 下 A 更好、B 更差，训练想让模型以后更像 A。然后再分三步解释 RM、RLHF、DPO。不要先从方法名开始。

### P1-10

- 章节名：14. 推理机制与生成参数
- 具体位置/小标题：推理性能指标：TTFT、tokens/s、latency、throughput
- 我卡住的点：这一节很实用，但指标多。TTFT、tokens/s、latency、throughput 都懂一点，可是没有一个完整请求的时间线，我难以把它们放到同一张图里。
- 建议怎么补：加一个具体例子：输入 2000 token，prefill 用 1.2s，所以 TTFT 约 1.4s；输出 300 token，每秒 50 token，decode 约 6s；总 latency 约 7.4s。这样我能立刻把指标连起来。

### P1-11

- 章节名：16. 大模型能做什么，不能做什么
- 具体位置/小标题：工程分工、最小判断框架
- 我卡住的点：这一节表格很有价值，但里面出现 IAM、ACL、RBAC、ABAC、workflow、trace、幂等、事务、回滚等词。作为小白，我知道它们都和工程可靠性有关，但不知道每个词是什么意思。
- 建议怎么补：加一个“工程词小抄”：权限系统、状态机、幂等、trace、workflow、事务、回滚，每个一句话。这样读表时不会因为词不懂而中断。

## P2：可优化问题

### P2-1

- 章节名：03. 从线性模型到神经网络
- 具体位置/小标题：图解导读、直觉层：从一条线到很多个小判断
- 我卡住的点：这一节用了线性分类、诈骗邮件、猫图识别几个例子。每个例子都能懂，但来回切换会稍微分散注意力。
- 建议怎么补：选一个主例子贯穿，比如一直用“垃圾邮件识别”讲线性模型、隐藏层、小判断器；猫图例子可以作为旁例，不要和主线平分篇幅。

### P2-2

- 章节名：07. 从现实世界到向量表示
- 具体位置/小标题：为什么文字比图片更麻烦
- 我卡住的点：文中说“图片天然就是数字矩阵”，这个说法容易让我误解成图片比文本简单很多。后来我才意识到像素虽然是数字，但“数字矩阵”也不等于模型理解图片。
- 建议怎么补：加一句“图片像素已经是数字，但仍然只是低层表示，模型还要学习边缘、纹理、形状等抽象特征”。这样不会把“数字化”和“理解”混为一谈。

### P2-3

- 章节名：08. 从文字到 token 和 embedding
- 具体位置/小标题：整节结构
- 我卡住的点：这一节比前面明显长很多，概念也多：编号、one-hot、tokenizer、embedding、训练、向量相似、上下文窗口、成本、截断。我能读懂，但读到后面会忘记前面。
- 建议怎么补：在中间加 2-3 个“到这里先记住”的短小结。例如 tokenizer 之后小结一次，embedding 之后小结一次，上下文窗口之前再提醒它为什么和工程有关。

### P2-4

- 章节名：09. 语言模型为什么预测下一个 token、10. 为什么预测下一个 token 会产生能力
- 具体位置/小标题：为什么这不是查数据库、常见误解
- 我卡住的点：这两节一直在区分“生成高概率文本”和“事实正确”。这很重要，但“理解”这个词还是有点摇摆：有时像是在说模型不理解，有时又说有功能性理解。
- 建议怎么补：在第 10 节开头明确约定：“本章说的理解，指能利用上下文和模式完成任务，不指人类意识或主观体验。”这样后面读起来不纠结。

### P2-5

- 章节名：15. 模型评测与工程验证
- 具体位置/小标题：Golden dataset、评测报告应该怎么写
- 我卡住的点：golden dataset 的字段表很好，但我还缺一个真实小样本。比如一条 input、expected、rubric、must_not 长什么样。
- 建议怎么补：加一个 3 行的小型 golden dataset 示例，最好覆盖事实问答、JSON 输出、拒答边界。这样我能把评测从概念变成可操作的文件。

### P2-6

- 章节名：多章节图示，尤其 08、11、12、14、15、16
- 具体位置/小标题：每节开头的 4 张图
- 我卡住的点：每节都有 4 张图，但很多图是重复出现或提前预告后文的。统计上，`training-alignment-pipeline.svg` 和 `next-token-loop.svg` 各出现 5 次，`transformer-block-stack.svg`、`gradient-descent-landscape.svg`、`forward-backprop-flow.svg`、`context-assembly-pipeline.svg` 各出现 4 次。重复本身不是坏事，但有些图放在概念解释前面，我看了也不知道该看哪里。
- 建议怎么补：每节开头保留 1 张最贴近本节的新图，其他图放到相关小标题下面再出现。重复图旁边要标明“这次看图里的哪一部分”，例如第 14 节看 prefill/decode，第 16 节再看上下文装配和工具闭环。

## 最应该优先修的 5 个点

1. 修正第 02 节“连接到下一节”的顺序错误，否则读者会直接在第一个基础链路上迷路。
2. 给第 11 节 Attention 公式补一个 3-token 的极小计算例子，这是后面 Transformer、KV cache、长上下文的基础。
3. 重整每节开头的 4 张图：减少重复预告图，把图放到正文用得上的位置。
4. 给第 12-16 节增加“高级术语先不用深究”的小抄，尤其 RoPE、RMSNorm、MQA/GQA、MoE、RLHF、DPO、trace、幂等等。
5. 在第 16 节加入一个完整 Agent 小任务例子，把模型、RAG、工具、状态、权限、评测和日志串成一条真实流程。
