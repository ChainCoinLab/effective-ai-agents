# 大模型基础 01-16 高级编辑复审（Round 2）

## 总判断

本轮修订对 Round 1 的编辑层问题有局部缓解，尤其是 `README.md` 和 `SUMMARY.md` 的入口、阅读顺序、工程术语预告、从大模型边界到 Agent 工程的承接，都比上一轮清楚。若读者只从目录进入，已经更容易知道“为什么按 01-16 读”。

但本轮主要是补说明、补例子、补表格，没有处理 Round 1 中最重的结构性问题：章首多图仍集中堆叠，长章节仍未压缩，文件名编号仍与展示编号错位，正文标题层级仍有明显模板感。因此，编辑层 P1 只缓解了导航入口，未真正缓解图文混排和篇幅密度；P2 在局部术语说明和过渡句上有改善，但表格密度和章节节奏问题仍在。

## Round 1 P1/P2 缓解情况

### P1-1 章首多图堆叠：未实质缓解

本轮在多章增加了“图解导读”，例如 `01-llm-history.md`、`06-attention-from-context.md`、`09-training-and-alignment.md`、`10-inference-and-parameters.md`、`12-evaluation.md`、`16-llm-capabilities-boundaries.md`。这让读者知道图的大致作用，比 Round 1 完全堆图更好。

但多图仍集中放在章首，且通常是 4 张连续图。图前导语只有总览式一句，没有把每张图移到对应概念首次讲解处，也没有逐图建立“看图任务 -> 正文解释 -> 图后收束”。因此该 P1 仍成立。

### P1-2 长章节节奏失衡：未缓解，局部加重

`03-token-and-embedding.md`、`04-next-token-prediction.md`、`05-capability-from-prediction.md`、`09-training-and-alignment.md`、`10-inference-and-parameters.md`、`12-evaluation.md` 仍是明显长章。其中 `03-token-and-embedding.md`、`05-capability-from-prediction.md`、`09-training-and-alignment.md` 行数接近或超过 600 行。

本轮新增解释和表格提升了局部清晰度，但没有做“主线压缩 + 备查下沉”。对连续阅读来说，密度问题没有缓解。

### P1-3 README / SUMMARY 导航：明显缓解，但仍有维护风险

`README.md` 已增加正式阅读顺序说明，并明确“部分文件名保留早期编号，以本表和 SUMMARY 为准”。`SUMMARY.md` 也加入本章导读入口，并把栏目名改为“大模型基础与工程边界”。这两点有效缓解了 Round 1 的入口不稳定问题。

剩余问题是文件系统里的正式章节编号仍不连续，旧稿和新稿仍并存。对网页读者影响降低，但对编辑、审校、跨文件引用和后续 agent 协作仍有风险。

### P2-1 标题模板化：未明显缓解

正文里“直觉层 / 机制层 / 形式层 / 工程层”“它从哪里来 / 它是什么 / 它怎么工作”等标题仍大量显性出现。`README.md` 还进一步强化了“每个核心概念至少讲到四层”的写法标准。

作为写作检查表这是有用的；作为成稿标题则仍显机械，长章节尤其明显。

### P2-2 表格和代码块密度：局部改善解释，整体负担增加

新增对照表和小例子解决了一些理解断点，例如 `03-token-and-embedding.md` 的 token id / token embedding / 上下文化表示 / text embedding 对照，`09-training-and-alignment.md` 的 Transformer / Pretraining / SFT / RLHF / DPO / Inference 分层表，`12-evaluation.md` 的最小 golden dataset 示例。

但这些新增内容叠加在原本已高密度的长章里，使表格数量、四列表和代码块继续增多。它们是“有帮助的新增”，但不是“减负式编辑”。

## 仍存在的编辑问题

### 1. 章首多图仍像素材索引，而不是讲解现场

- 定位：`doc/agent-best-practices/00-llm-basics/06-attention-from-context.md`《11. 从上下文问题到 Attention》；`10-inference-and-parameters.md`《14. 推理机制与生成参数》；`12-evaluation.md`《15. 模型评测与工程验证》；`16-llm-capabilities-boundaries.md`《16. 大模型能做什么，不能做什么》。
- 问题表现：每章开头仍连续出现 4 张图。比如《推理机制与生成参数》同时放 prefill/decode、Transformer block、next-token loop、context assembly；《模型评测与工程验证》同时放评测闭环、训练对齐、推理、能力边界。新增“图解导读”是总览句，没有逐图解释。
- 为什么影响阅读：读者在概念尚未建立前被迫面对多个层级的图，容易跳过图或误以为这些图都需要立刻理解。图没有进入对应段落现场，就难以承担降低理解门槛的功能。
- 建议怎么改：每章章首只保留 1 张总览图。其余图移动到第一次讲到对应概念的小节前后，例如 Transformer block 放在解释模型结构时，context assembly 放在讲上下文装配时。每张图前写一句“这张图只看哪一层关系”，图后写 1-2 句“读完本段应带走什么”。

### 2. `README.md` 本身从导读变成小型正文，入口密度偏高

- 定位：`doc/agent-best-practices/00-llm-basics/README.md`《阅读约定》《每节写法》《讲透标准》《最终落点》《能力边界》。
- 问题表现：README 新增术语表、图示读法、写法链路、讲透标准、四层表、最终落点和能力边界。信息完整，但作为入口页已经偏长，且后半部分与第 16 章《大模型能做什么，不能做什么》有内容重叠。
- 为什么影响阅读：导读页应帮助读者建立路线和使用方法。现在它同时承担目录、术语预告、写作规范、能力边界总结，读者还没进入正文就要消化大量元信息。
- 建议怎么改：README 保留“总主线、章节框架、阅读约定、最终落点”四块即可。把“每节写法”和“讲透标准”移到作者编辑规范或 review notes；“能力边界”压缩成 3-5 句，并把完整展开留给第 16 章。

### 3. 文件名编号与展示编号仍不一致，已降低但未消除维护成本

- 定位：`doc/agent-best-practices/00-llm-basics/README.md`《章节框架》；`doc/agent-best-practices/SUMMARY.md`《一、大模型基础与工程边界》。
- 问题表现：展示编号 07 链到 `02-real-world-to-vectors.md`，08 链到 `03-token-and-embedding.md`，13 链到 `09-training-and-alignment.md`，15 链到 `12-evaluation.md`。README 已说明“以本表和 SUMMARY 为准”，但文件系统仍保留多套历史稿和错位编号。
- 为什么影响阅读：网页阅读已可接受，但编辑协作、交叉引用、审校记录和后续重构时仍容易引用错文件。这个问题会持续消耗维护注意力。
- 建议怎么改：短期保留 README 说明；下一轮结构性修订时统一正式文件名编号，旧稿移入 `archive/` 或加 `legacy-` 前缀。若暂不重命名，建议在每个正式文件顶部加入“正式章节序号”元信息，降低误引。

### 4. 长章仍以“完整覆盖”替代“主线推进”

- 定位：`doc/agent-best-practices/00-llm-basics/03-token-and-embedding.md`《08. 从文字到 token 和 embedding》；`05-capability-from-prediction.md`《10. 为什么预测下一个 token 会产生能力》；`09-training-and-alignment.md`《13. 预训练、指令微调与对齐》；`12-evaluation.md`《15. 模型评测与工程验证》。
- 问题表现：这些章节持续采用多层解释、表格、伪公式、工程补位和误解清单的全覆盖写法。新增表格提高了局部可理解性，但没有压缩主线。例如 `03-token-and-embedding.md` 同时讲编号、one-hot、tokenizer、embedding、训练来源、向量空间、上下文化表示、成本、截断、误解，阅读跨度很大。
- 为什么影响阅读：长章不是不能长，但每节都完整铺四层，会让读者难以区分“本节必须掌握的主判断”和“工程备查”。连续阅读时，核心推导线会被局部解释淹没。
- 建议怎么改：每个长章开头明确“本节只要求带走 3 个判断”。正文围绕这 3 个判断组织；公式、参数细节、长表格、误解清单下沉到“进阶阅读 / 工程备查”。`03-token-and-embedding.md` 可考虑拆成“tokenization”和“embedding / 表示空间”两个独立小章或内部大段。

### 5. 新增表格有帮助，但与既有表格叠加后增加版面负担

- 定位：`03-token-and-embedding.md`《常见误解》新增向量对照表；`09-training-and-alignment.md`《核心问题》新增结构与训练阶段分层表；`12-evaluation.md`《Golden dataset：固定测试集是评测的地基》新增最小 golden dataset 表；`16-llm-capabilities-boundaries.md`《大模型不是什么》新增工程词小抄。
- 问题表现：新增表格大多命中 Round 1 的理解问题，但它们被放进原本已经表格密集的章节。尤其第 16 章连续出现“不是什么”四列表、工程词小抄、场景分工表，页面节奏偏硬。
- 为什么影响阅读：表格适合比较和查阅，但连续表格会让教材从“讲解”变成“资料清单”。移动端或 GitBook 窄屏下，四列表容易横向拥挤，读者也更难读出作者要强调的结论。
- 建议怎么改：保留解决关键混淆的表，例如 `03-token-and-embedding.md` 的向量对照表；把工程备查型表格压缩为列表或移到附录。每张表后都加一句结论句，明确“所以这里要记住的是……”。超过 4 列的表优先拆成两张或改为分组列表。

### 6. 标题层级仍像写作模板，成稿感不足

- 定位：`03-token-and-embedding.md`《文字为什么不能直接进模型》下的“直觉层 / 机制层 / 形式层 / 工程层”；`05-capability-from-prediction.md`多个能力小节；`09-training-and-alignment.md`《7. reward model、RLHF 与 DPO》下的 7.1-7.4；`README.md`《每节写法》《讲透标准》。
- 问题表现：四层标题仍被大量显性化，且与“它从哪里来 / 它是什么 / 它怎么工作”混用。读者看到的是编辑提纲，而不是自然成稿标题。
- 为什么影响阅读：模板标题能保证覆盖度，但过多会削弱叙事流动。重要结论和写作检查项权重相同，读者难以扫描出真正的知识节点。
- 建议怎么改：四层结构保留为内部写作标准，正文标题改成问题式或结论式。例如“机制层”改成“token id 只是查表键，不是语义数值”；“工程层”改成“为什么 token 预算会影响 RAG 切块和成本”。

### 7. SUMMARY 已补承接，但层级呈现还有轻微割裂

- 定位：`doc/agent-best-practices/SUMMARY.md`《一、大模型基础与工程边界》《二、Agent 开发》。
- 问题表现：SUMMARY 已新增 Agent 承接段，这一点明显改善。但 01-16 作为平级列表全部铺开，和后续 Agent 开发同样是平级列表，缺少内部分组。
- 为什么影响阅读：16 个连续条目对目录页来说较长，读者需要自己识别“机器学习基础、表示与语言模型、架构训练推理评测、能力边界”这几个阶段。
- 建议怎么改：在 SUMMARY 或 README 章节框架中增加轻量阶段分组，例如“01 总览”“02-06 机器学习基础”“07-12 表示与架构”“13-16 训练、推理、评测和边界”。SUMMARY 不一定嵌套过深，但可用短说明分段。

### 8. 局部新增过渡段改善断点，但尚未形成统一收束模式

- 定位：`10-inference-and-parameters.md`《核心问题》；`12-evaluation.md`《14. 收束：评测暴露模型边界》；`16-llm-capabilities-boundaries.md`末尾承接 Agent。
- 问题表现：第 14 章开头明确区分第 09 节采样机制与本节工程化推理，这是有效改进；第 15 章结尾也能自然进入能力边界。但其他章节仍常以“连接到下一节”完成目录式跳转，没有稳定形成“本节判断 -> 仍未解决的问题 -> 下一节为什么必要”的三句收束。
- 为什么影响阅读：本系列的价值在于连续推导。若每章结尾只是介绍下一章主题，读者会把章节看成并列知识点，而不是一步步收紧到工程边界。
- 建议怎么改：统一每章结尾写法：第一句给本节最终判断，第二句指出该判断还解决不了什么，第三句说明下一节为什么必须出现。保留“连接到下一节”标题也可以，但正文要承担推导功能。

## 本轮新增内容是否引入新的版面负担

结论：有，主要是“局部解释变清楚，整体密度继续上升”。

新增内容中，`README.md` 的阅读顺序说明、`SUMMARY.md` 的导读入口和 Agent 承接段、`09-training-and-alignment.md` 的结构/训练阶段分层表、`03-token-and-embedding.md` 的向量对照表，都是有效补丁。

新的负担来自三个方面：

1. README 从入口导读扩展成写作规范和能力边界摘要，页内职责过多。
2. 长章新增表格和例子后，没有同步删减旧解释，导致表格、伪公式、误区清单继续累积。
3. 图解导读降低了一点章首多图压力，但多图位置没变，图文混排问题仍被保留下来。

因此，本轮新增内容不算“错误新增”，但属于“加法修订”。下一轮如果继续只加说明，会进一步加重版面密度；应改为减法和重排。

## 是否建议进入下一轮修订

建议进入下一轮修订，但不建议继续做零散补充。下一轮应定位为结构性编辑轮，优先级如下：

1. 先处理图文混排：每章章首只留总览图，其余图进入对应小节。
2. 再处理长章密度：`03-token-and-embedding.md`、`05-capability-from-prediction.md`、`09-training-and-alignment.md`、`12-evaluation.md` 做主线压缩和备查下沉。
3. 然后统一标题成稿感：减少“直觉层 / 机制层 / 形式层 / 工程层”显性标题。
4. 最后处理导航维护问题：正式文件名编号、旧稿归档、SUMMARY 阶段分组。

当前版本可以作为内容底稿继续打磨，但还不建议进入最终校对或发布态排版。
