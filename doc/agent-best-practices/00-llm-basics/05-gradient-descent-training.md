## 核心问题

知道梯度之后，参数到底怎么被优化？

上一节讲了前向传播、损失函数和反向传播。它们让模型完成了三件事：

这张图只用来回看上一节职责：前向传播算预测，损失函数判分，反向传播算梯度。

![前向传播、损失函数与反向传播流程](../assets/diagrams/forward-backprop-flow.svg)

```text
算出预测
→ 衡量错误
→ 计算每个参数对错误的影响
```

但梯度只是告诉我们“往哪个方向调参数，损失可能下降”。真正的训练还需要决定：

```text
每次调多大？也就是学习率如何设置
每次用多少样本估计梯度？也就是 batch 如何设置
完整数据要看几遍？也就是 epoch 如何设置
参数更新规则是否只用当前梯度？也就是 optimizer 如何选择
训练不稳定时怎么看日志、怎么调参？
```

**学习率**是每次参数更新的步长，**batch** 是一次训练步使用的一小批样本，**epoch** 是完整遍历训练集一遍，**optimizer** 是根据梯度更新参数的算法。这些问题共同构成模型训练。训练不是一次性把参数算出来，而是反复执行“前向、算损失、反向、更新”的循环。

初学者先掌握这四个就够了：learning rate、batch、epoch、optimizer。后面出现的 Adam、Momentum、grad norm、warmup、decay、梯度裁剪等，先理解成“让训练更稳定、更高效的工程技巧”，不需要在第一次阅读时全部吃透。

## 从哪里来：从梯度到参数更新

**梯度下降**是一类优化方法，目标是让损失函数越来越小。直觉上，损失函数像一片地形，当前位置是当前参数，海拔是损失值。梯度指向损失上升最快的方向，所以要让损失下降，就沿着梯度的反方向走。

最基本的更新公式是：

```text
theta = theta - learning_rate * gradient
```

这里：

- `theta` 表示模型的所有参数。
- **learning rate** 也叫**学习率**，表示每次更新参数的步长。
- `gradient` 是损失对参数的梯度。

学习率是训练里最重要的超参数之一。**超参数**是训练前由人或调参系统设置的配置，不是模型从数据中直接学出来的参数。

如果学习率太小，模型每次只走很短一步，训练会很慢，甚至看起来停滞。如果学习率太大，模型可能越过低损失区域，在两侧来回震荡，甚至让损失爆炸。

## 直觉层：下山、步幅和路况

可以把训练想象成蒙着眼下山：

```text
脚下坡度 = 梯度
下山方向 = 负梯度方向
迈步大小 = 学习率
地形高度 = 损失
当前位置 = 当前参数
```

你不能直接看到整座山，只能根据当前位置附近的坡度判断下一步。每走一步，位置变了，坡度也会变，所以要反复重新计算梯度。

这也解释了为什么训练会有震荡。若步子太大，可能从山谷左边跨到右边，再从右边跨回左边；若数据本身有噪声，每次估计出来的坡度也会抖动。

真实神经网络的损失地形不是二维山谷，而是高维空间。每个参数都是一个方向，大模型有海量参数，所以它的“地形”极其复杂。工程上我们不指望画完整地形，而是通过训练日志、验证集表现和稳定性指标判断优化是否健康。

## 机制层：batch、epoch 和 step

训练数据通常很大，不会每次更新都用完整数据集。这里需要三个术语。

**batch** 是一次训练步中使用的一小批样本。比如有 100 万条样本，每次拿 256 条计算一次平均损失和梯度，这 256 条就是一个 batch。

这张图只用来看训练循环的时间顺序：取样本、前向、算损失、反向、更新，然后进入下一轮。

![机器学习训练循环](../assets/diagrams/training-loop-ring.svg)

**step** 是一次参数更新。通常一次 step 包含：

```text
取一个 batch
→ 前向传播
→ 计算 batch 平均损失
→ 反向传播
→ 优化器更新参数
```

**epoch** 是完整遍历训练集一遍。假设训练集有 10000 条样本，batch size 是 100，那么一个 epoch 大约有 100 个 step。

这三个词经常一起出现，但它们指向的时间尺度不同。可以用下面的表把它们分开看：

| 概念 | 直接含义 | 例子 | 主要影响 |
| --- | --- | --- | --- |
| batch | 一次 step 使用的一小批样本 | 从训练集中取 256 条样本 | 梯度噪声、显存占用、吞吐 |
| step | 一次参数更新 | 用一个 batch 算损失、反传并更新参数 | 训练进度、学习率调度、日志横轴 |
| epoch | 完整遍历训练集一遍 | 10000 条样本、batch size 100，大约 100 step | 数据利用次数、过拟合风险、评估节奏 |

因此，日志里看到的 `step=1000` 不等于模型已经看过 1000 遍数据；它只说明参数更新了 1000 次。是否已经完成几个 epoch，要结合训练集大小和 batch size 计算。

为什么不用全部数据每次更新？原因很现实：

- 全量数据计算太慢，显存或内存可能放不下。
- 小批量更新更频繁，可以更快开始下降。
- batch 带来的随机性有时能帮助模型跳出某些不好的区域。

但 batch 也不是越小越好。batch 太小，梯度估计噪声大，训练曲线会很抖；batch 太大，计算成本高，也可能影响泛化。工程上常见做法是根据显存、吞吐、稳定性和效果选择 batch size。

## 机制层：optimizer 不只是普通梯度下降

**optimizer** 也叫优化器，是根据梯度更新参数的算法。最朴素的优化器是随机梯度下降，也就是 **SGD**。它直接用当前 batch 的梯度更新参数：

```text
theta = theta - lr * grad
```

但深度网络训练经常需要更稳定、更快的更新规则，所以出现了很多优化器。

**Momentum** 是在更新时加入“惯性”。如果前几步都朝相似方向下降，Momentum 会让这个方向的更新更强；如果梯度在某个方向来回震荡，它会抵消一部分抖动。

**Adam** 是深度学习中非常常用的优化器。它会为每个参数维护梯度的一阶估计和二阶估计。简单说，它既看梯度的平均方向，也看梯度波动大小，从而给不同参数使用自适应步长。

下面这个对照表只抓工程直觉，不要求一开始记住公式：

| 优化器 | 更新直觉 | 优点 | 常见注意点 |
| --- | --- | --- | --- |
| SGD | 直接沿当前 batch 的负梯度方向走 | 简单、可解释、基线清晰 | 对学习率敏感，复杂网络中可能收敛慢 |
| Momentum | 在梯度方向上加入历史惯性 | 能减轻来回震荡，加快稳定方向上的下降 | 惯性太强时可能冲过低损失区域 |
| Adam | 根据梯度均值和波动自适应调整每个参数步长 | 深度学习中常用，前期训练通常更稳 | 仍需要合适学习率，权重衰减等配置要配套 |

实际项目里，优化器选择通常和学习率计划、batch size、权重衰减一起调。单独换优化器可能有帮助，但不能替代数据检查和训练日志分析。

不需要一开始记住所有优化器细节，但要知道：

```text
反向传播负责算梯度
优化器负责用梯度改参数
不同优化器代表不同的更新策略
```

在大模型训练中，优化器、学习率计划、batch size、权重衰减、梯度裁剪和混合精度都会显著影响训练能否稳定进行。

## 形式层：训练循环长什么样

一个标准训练循环可以写成伪代码：

```text
初始化参数 theta

for epoch in range(num_epochs):
    for batch in dataloader:
        x, y = batch

        y_hat = model(x)              # 前向传播
        loss = loss_fn(y_hat, y)      # 计算损失

        gradients = backward(loss)    # 反向传播
        optimizer.step(gradients)     # 更新参数
        optimizer.zero_grad()         # 清空旧梯度

    在验证集上评估模型
```

真实框架里，清空梯度通常出现在反向传播前或参数更新后。关键是不能让上一个 batch 的梯度意外累积到下一个 batch，除非你明确在做梯度累积。

**梯度累积**是指多个小 batch 分别反向传播，把梯度累积起来，再统一更新一次参数。它常用于显存不够但想模拟更大 batch 的场景。

训练循环的核心目标是让训练损失下降，但健康训练通常还要同时观察验证集指标。验证集不是用来更新参数的，而是用来估计模型在未参与训练的数据上表现如何。

## 工程层：训练日志怎么看

训练日志不是装饰，它是判断模型是否正常学习的仪表盘。常见日志包括：

- **train loss**：训练集或训练 batch 上的损失。
- **val loss**：验证集上的损失。
- **accuracy**：分类任务中预测正确的比例。
- **learning rate**：当前学习率。
- **grad norm**：梯度范数，表示整体梯度大小。
- **throughput**：吞吐量，例如每秒处理多少样本或 token。
- **memory usage**：显存或内存占用。

几种常见现象：

训练异常最好先按现象归类，再决定该查数据、超参数还是数值稳定性。下面的表可以作为第一轮排查清单：

| 日志现象 | 常见含义 | 优先排查方向 | 常见处理 |
| --- | --- | --- | --- |
| train loss 基本不降 | 模型没有学到有效信号 | 数据标签、输入预处理、学习率、模型输出范围 | 先跑小数据集验证能否过拟合，再调学习率 |
| train loss 降，val loss 升 | 训练集适应过强 | 过拟合、数据泄漏、验证集分布 | 早停、正则化、去重、检查划分方式 |
| loss 变成 NaN | 数值已经不稳定 | 学习率、梯度爆炸、异常样本、混合精度 | 降学习率、梯度裁剪、定位异常 batch |
| loss 大幅震荡 | 每次更新方向不稳定 | 学习率过高、batch 太小、梯度噪声大 | 降学习率、增大 batch 或做梯度累积 |
| 吞吐很低但 loss 正常 | 优化方向没问题，系统效率低 | 数据加载、显存利用率、通信开销 | profile 数据管道和硬件利用率 |

表格里的处理不是固定答案，而是帮助你把“看见曲线异常”变成“提出可验证假设”。

```text
train loss 不降
→ 学习率可能太小或太大，模型容量不足，数据或标签有问题，输入预处理有 bug

train loss 下降但 val loss 上升
→ 模型可能开始过拟合

loss 突然变成 NaN
→ 学习率过大、数值溢出、数据异常或混合精度不稳定

loss 大幅上下震荡
→ 学习率可能过高，batch 太小，梯度噪声太大

训练很慢但曲线正常
→ 可以检查 batch size、数据加载、硬件利用率和模型实现
```

**NaN** 是 not a number 的缩写，表示计算结果不是合法数字。训练里一旦出现 NaN，后续参数很可能被污染，需要及时定位原因。

工程调参通常不是盲目试，而是根据日志提出假设。比如 train loss 完全不动，先检查数据和标签，再检查学习率和模型输出；如果 train loss 很好但 val loss 变差，重点检查过拟合、数据泄漏和正则化。

## 局部最小、鞍点和震荡

**局部最小值**是指在附近区域内损失最低的位置，但不一定是全局最低。初学者常担心模型会卡在局部最小值。这个问题存在，但在现代深度网络里，另一个常见问题是**鞍点**。

**鞍点**是指某些方向看起来像最低点，另一些方向还能继续下降的位置。高维空间里鞍点很多。优化器、随机 batch 和合适学习率通常能帮助模型继续移动。

**震荡**是指损失在下降方向附近来回摆动。常见原因包括学习率太大、梯度噪声太强或不同参数方向尺度差异很大。处理方法包括：

- 降低学习率。
- 使用学习率 warmup 或 decay。
- 增大 batch size 或使用梯度累积。
- 使用 Adam、Momentum 等优化器。
- 做梯度裁剪，限制过大的梯度。
- 检查输入归一化和标签质量。

**warmup** 是训练早期从较小学习率逐步升到目标学习率的方法，常用于稳定大模型训练。**decay** 是训练过程中逐渐降低学习率的方法，用于让后期更新更精细。

## 工程层：训练不是只看一个数

训练一个模型，至少要同时管理四件事：

这张图只用来预告下一节：训练损失下降后，还要判断模型是在泛化，还是在记住训练样本。

![欠拟合、合适拟合与过拟合对比](../assets/diagrams/overfitting-generalization.svg)

```text
优化：损失能否下降
泛化：验证集是否变好
效率：训练是否足够快、成本是否可接受
稳定性：是否出现爆炸、NaN、发散或不可复现
```

对于大模型，还要关注：

- token 吞吐和显存利用率。
- checkpoint 保存和恢复。
- 分布式训练通信开销。
- 数据去重和数据混合比例。
- 长序列带来的显存和注意力计算成本。
- 训练后评测是否覆盖真实任务。

这说明“训练”不是一句“跑一下代码”。它是一套工程系统：数据管道、模型结构、损失函数、优化器、日志、评测、硬件和故障恢复共同决定最终结果。

## 常见误区

**误区一：梯度下降一定会找到全局最优。**  
深度网络的损失地形很复杂，梯度下降通常只能找到足够好的解，而不是证明意义上的全局最优。

**误区二：学习率越大训练越快。**  
学习率大可能前期下降快，也可能直接发散。学习率要和模型、batch size、优化器、数据规模一起调。

**误区三：batch 越大越好。**  
大 batch 提高硬件吞吐，但不一定带来更好泛化，还可能需要配套调整学习率和训练步数。

**误区四：train loss 下降就可以停止分析。**  
train loss 只说明模型更适应训练数据。是否真正学到规律，要看验证集、测试集和真实任务指标。

**误区五：optimizer 可以弥补所有数据问题。**  
优化器只能改善参数更新方式，不能修复错误标签、数据泄漏、分布不匹配和任务定义混乱。

训练循环的目标是让损失下降，但损失下降有两种可能：模型真的学到了可迁移规律，也可能只是把训练样本记住了。前者叫泛化，后者会走向过拟合。
