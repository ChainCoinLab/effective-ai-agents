# 00.11 工具调用基础

[返回全局摘要](../README.md) · [返回本组：AI 工程基础知识与原理](README.md)

工具调用让模型从“只能生成文本”扩展到“可以请求外部系统执行动作”。它是 Agent 能连接真实世界的关键能力。

## 工具调用解决什么问题

模型本身不能直接：

- 查询实时数据库。
- 访问业务系统。
- 运行代码。
- 搜索网页。
- 创建工单。
- 发邮件。
- 修改订单或配置。

工具调用让模型提出调用意图，由应用或协议层执行真实动作，并把结果作为 observation 返回给模型。

## 基本流程

```text
用户目标
  -> 模型判断需要工具
  -> 生成工具名和参数
  -> 应用校验权限和参数
  -> 执行工具
  -> 返回结构化结果
  -> 模型基于结果继续回答或下一步
```

## 工具和 MCP 的关系

工具调用是一种动作机制，MCP 是标准化暴露这些工具和资源的一种协议。

可以这样理解：

- Tool 是“可以做什么”。
- MCP 是“用什么标准方式发现、描述和调用这些能力”。
- Agent 是“什么时候调用、为什么调用、调用后怎么继续”。

因此工具调用可以放在 MCP 章节里理解连接方式，也可以在 Agent 章节里理解执行动作。基础知识里单独成篇，是为了先把“动作能力”这个概念讲清楚。

## 工程风险

工具调用最容易出问题的地方：

- 参数错误。
- 权限越界。
- 重复执行写操作。
- 工具失败后模型继续编造结果。
- 返回结果只有自然语言，无法验证。
- 删除、发布、付款等高风险动作没有确认。

## 工程原则

- 工具接口要小而清晰。
- 参数和返回值要结构化。
- 应用层负责权限，不让模型直接决定能否执行。
- 写操作要幂等、可审计、可回滚。
- 高风险动作必须人工确认。
- 工具失败是正常路径，要有错误类型和恢复建议。
