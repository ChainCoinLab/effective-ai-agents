# 01. 大模型发展历史

[返回本章](README.md)

![大模型结构演进](../assets/diagrams/model-evolution.svg)

图解导读：先只看结构演进图，抓住“大模型怎样从语言模型走向 Transformer、指令模型和 Agent 系统”的主线。

## 核心问题

大模型的发展路线是什么？它为什么会从早期语言模型走到 Transformer、GPT、指令微调、长上下文、多模态和 Agent？

这一节只做总览，不展开训练细节、特征向量细节和多模态实现细节。它的任务是先给读者一张地图：大模型不是突然出现的，而是机器学习、神经网络、语言建模、注意力机制、算力和数据规模长期叠加的结果。

如果你是第一次读，这一节只需要形成三个印象：

- 大模型不是一开始就存在的，而是从“机器如何从数据中学习规律”一步步发展出来的。
- RNN、LSTM、Attention、Transformer、RLHF、DPO、RAG、Agent 这些词现在只要知道它们各自解决什么问题，后面会逐个拆开。
- 下一节会暂时放下这些大词，回到最小结构 `输入 x -> 模型 f -> 输出 y`。

## 总览路线

```text
机器从数据中学习规律
→ 语言可以被建模成序列预测问题
→ 统计语言模型根据短上下文预测下一个词
→ 神经网络语言模型把词变成向量
→ RNN / LSTM 按顺序处理文本
→ Seq2Seq 处理输入序列到输出序列
→ Attention 让模型直接关注相关位置
→ Transformer 用 Self-attention 统一建模上下文关系
→ BERT / GPT 形成理解路线和生成路线
→ GPT-3 级别的大模型通过规模获得更强泛化能力
→ Instruction Tuning / RLHF / DPO 让模型更会听指令
→ 长上下文、多模态、工具调用和 Agent 扩展模型使用方式
```

这条路线不要理解成“技术名词越来越多”，而要理解成连续解决同一个问题：

```text
怎样让机器从数据中学到更复杂的规律？
怎样让机器表示语言？
怎样让模型看到更长、更相关的上下文？
怎样让模型从续写文本变成按指令完成任务？
怎样让模型进入真实工程系统？
```

每一次架构变化，背后都有一个旧方法解决不了的问题。

| 阶段 | 解决了什么 | 仍然解决不了什么 | 为什么引出下一步 |
| --- | --- | --- | --- |
| 手写规则 | 规则清楚的确定性任务 | 规则复杂、变化快、边界多的任务 | 需要从数据中学习模式 |
| 统计语言模型 | 用短上下文预测下一个词 | 上下文短，语义弱，组合泛化差 | 需要词向量和神经网络 |
| RNN / LSTM | 按顺序处理文本，保存历史状态 | 长距离信息容易丢，训练难并行 | 需要直接关注相关位置 |
| Attention | 让当前位置直接看相关上下文 | 还需要更适合规模化训练的整体结构 | 引出 Transformer |
| Transformer | 全局关系建模和并行训练 | 预训练模型只是会续写，不一定听指令 | 引出 SFT、RLHF / DPO |
| GPT 类大模型 | 用生成任务统一很多文本任务 | 事实、权限、状态、执行仍不可靠 | 引出 RAG、工具和 Agent |

上表看的是阶段之间的接力。再换成工程视角，可以看到每个突破都同时带来新的系统问题：

| 阶段 | 核心突破 | 新问题 | 工程启发 |
| --- | --- | --- | --- |
| 从规则到机器学习 | 规则从人工编写变成从数据学习 | 数据质量和标签边界决定模型上限 | 不要只写规则，还要设计数据、反馈和评测 |
| 从统计模型到神经网络 | 词和语义关系开始被表示成向量 | 模型更难解释，训练更依赖算力 | 特征工程逐步转向表示学习 |
| 从 RNN 到 Attention | 相关位置可以直接交互 | 注意力计算和上下文长度带来成本 | 长文本系统要同时考虑相关性和预算 |
| 从 Attention 到 Transformer | 上下文建模和并行训练结合起来 | 大规模训练需要稳定工程栈 | 架构能力必须和数据、算力、训练流程配套 |
| 从 GPT 到对齐模型 | 续写能力被塑造成指令协作能力 | 偏好、安全和事实性不能只靠预训练 | 需要 SFT、偏好优化、红队和离线评测 |
| 从模型到 Agent 系统 | 模型可以接入知识、工具和状态 | 权限、可靠性、可观测性成为核心风险 | 把模型当成组件，而不是完整应用本身 |

另一种读法，是把历史拆成三层：底层解决“怎么表示和建模”，中层解决“怎么训练和对齐”，上层解决“怎么接入真实任务”。

| 层级 | 关注问题 | 代表技术 | 对后续章节的意义 |
| --- | --- | --- | --- |
| 能力底座层 | 输入如何变成数字，模型如何建立上下文关系 | 特征、token、embedding、神经网络、Attention、Transformer | 解释为什么大模型能表示语言并组合上下文 |
| 训练对齐层 | 模型如何从数据和反馈中改进 | 损失函数、反向传播、预训练、SFT、RLHF / DPO | 解释能力来自优化过程，而不是手写规则 |
| 工程接入层 | 模型如何进入产品和业务流程 | RAG、工具调用、Agent、评测、权限 | 解释为什么大模型应用必须补上外部系统边界 |

这样读历史，就不会把大模型只理解成一个更大的聊天框，而会看到它背后的能力底座、训练对齐和工程接入三条线索。

## 1. 第一阶段：从规则到学习

早期软件主要依靠人写规则，机器执行规则。但现实任务里，很多规则写不完：图片识别、垃圾邮件过滤、语音识别、自然语言理解都会遇到大量变化和边界情况。

机器学习改变了规则来源：人不再枚举所有规则，而是提供数据、目标和反馈，让模型从样本中学习模式。这个思想是后面神经网络、深度学习和大语言模型的共同起点。

这里先只记住一句话：

```text
传统软件依赖显式规则
机器学习依赖训练出来的隐式模式
```

这张图只用来看一个转折：规则从“人手写”变成“模型从数据中学习”。

![传统编程和机器学习的差异](../assets/diagrams/rules-vs-machine-learning.svg)

具体的“二维坐标找线”和“猜、错、调、再猜”训练循环，放到下一节展开。

## 2. 第二阶段：从短上下文到长距离关系

语言模型最早可以理解成：根据前文预测下一个词。统计语言模型用 n-gram 做这件事，但它只能看很短的上下文，很难处理长距离依赖和复杂语义。

神经网络语言模型开始用向量表示词，让模型不再只把词当离散符号。RNN / LSTM 进一步把文本当成序列，按顺序读取，并用隐藏状态保存历史。

问题是：长文本信息容易在状态里丢失，训练也不容易并行。Seq2Seq 让模型能做翻译、摘要、问答这类输入到输出的任务，但仍然存在信息压缩瓶颈。

Attention 的关键变化是：模型生成当前位置时，可以直接看输入中相关的位置，而不是只依赖一个被压缩过的状态。

这张图只用来看序列建模的关键变化：从局部卷积、顺序状态，走向上下文位置之间的直接交互。

![CNN、RNN 和 Transformer 的差异](../assets/diagrams/cnn-rnn-transformer-comparison.svg)

## 3. 第三阶段：Transformer 成为主干

Transformer 把 Self-attention 变成核心结构，让每个 token 都能和上下文里的其他 token 建立关系，同时又适合大规模并行训练。

这一步很关键，因为大模型需要三件事同时成立：

- 能建模长距离上下文关系。
- 能利用大规模数据训练。
- 能被算力规模持续放大。

Transformer 同时满足这些条件，所以成为现代大语言模型的主干。

后面会专门拆 Transformer 的内部结构，包括 token、embedding、位置编码、Q/K/V、多头注意力、前馈网络、残差连接和 decoder-only 架构。

## 4. 第四阶段：从专用模型到通用生成模型

Transformer 之后出现了两条代表性路线：

- BERT 更偏理解，用双向上下文学习文本表示，适合分类、抽取、匹配等任务。
- GPT 更偏生成，用 decoder-only Transformer 做自回归 next-token prediction。

GPT 路线之所以能扩展成通用生成模型，是因为很多任务都可以改写成文本续写：给定任务说明、上下文、示例和约束，让模型继续预测后续 token。

模型规模、数据规模和算力继续增长后，模型开始表现出更强的上下文学习能力。它不一定需要为每个任务重新训练参数，只要在上下文里给出任务说明和少量示例，就能临时适配任务。

## 5. 第五阶段：从会续写到会按指令协作

预训练让模型学会语言、知识和模式，但预训练模型本质上还是“会续写”。要让它更像今天的 ChatGPT，还需要让它学会按人的意图回答。

这就引出了后续训练和对齐：

- Instruction Tuning / SFT：让模型学习按指令完成任务。
- RLHF / DPO：让模型输出更符合人类偏好和安全要求。
- 安全对齐：减少危险、越权、泄露和不合适输出。

这张图只用来看训练阶段的分工：预训练获得续写能力，指令微调和偏好优化把能力塑造成更适合人机协作的输出。

![预训练、指令微调与对齐流程](../assets/diagrams/training-alignment-pipeline.svg)

这一步之后，大模型才从“语言续写器”更接近“可对话、可解释、可协作的生成组件”。

## 6. 第六阶段：长上下文、多模态、工具和 Agent

大模型继续发展后，能力不只体现在模型参数本身，也体现在外部系统如何组织输入和任务：

- 长上下文让模型能看到更多材料，但也带来成本、排序和关键信息丢失问题。
- 多模态把图片、音频、视频等输入转成 token 或 embedding，再接入语言模型。
- 工具调用让模型提出调用意图，由外部系统执行确定性动作。
- Agent 把模型、上下文、工具、状态、权限和评测组织成任务流程。

这些内容后面都会单独展开。这里先建立一个总判断：

```text
大模型的发展不是从“不会”突然变成“万能”
而是一步步提升了表示能力、上下文建模能力、生成能力和工程接入能力
```

换句话说，历史总览要先建立边界感：Transformer 和 GPT 解决的是“如何更好建模上下文并生成 token”，不是把模型变成数据库、权限系统、状态机或执行器。后面的 RAG、工具调用和 Agent，正是为了补这些工程边界。

## 本节小结

- 大模型不是突然出现的，而是机器学习和语言建模长期演进的结果。
- 历史主线不是年份列表，而是“如何更好学习规律、表示语言、建模上下文、生成输出”。
- Transformer 成为主干，是因为它同时适合上下文关系建模和大规模并行训练。
- GPT 路线能成为通用生成模型，是因为 next-token prediction 可以统一大量文本任务。
- 指令微调和对齐让模型从“会续写”变成“更会按指令协作”。
- 长上下文、多模态、工具调用和 Agent 是大模型能力进入工程系统后的扩展方向。
