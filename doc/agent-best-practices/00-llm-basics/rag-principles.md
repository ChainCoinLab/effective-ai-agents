# 00.8 RAG 概念与原理

[返回全局摘要](../README.md) · [返回本组：AI 工程基础知识与原理](README.md)

RAG 是 Retrieval-Augmented Generation，检索增强生成。它的核心思想是：先从外部知识库检索相关证据，再把证据放入上下文，让模型基于证据生成答案。

## RAG 解决什么问题

RAG 解决的是知识边界和幻觉问题：

- 模型参数里没有企业内部知识。
- 模型不知道最新事实。
- 专业知识频繁更新，不适合频繁微调。
- 回答需要可追溯证据和引用来源。
- 模型容易在缺少依据时编造答案。

## 基本流程

```text
用户问题
  -> Query 改写
  -> 检索候选文档
  -> Rerank 重排
  -> 选择证据
  -> 注入上下文
  -> 生成答案
  -> 引用来源
```

## 关键组件

| 组件 | 作用 |
| --- | --- |
| 文档解析 | 把 PDF、网页、Markdown、数据库记录转成文本 |
| 分块 | 把长文档切成适合检索和生成的片段 |
| 向量检索 | 按语义相似度召回材料 |
| BM25 | 按关键词匹配召回材料 |
| 混合检索 | 同时利用关键词和语义召回 |
| Rerank | 对召回结果重新排序，提高证据质量 |
| 上下文压缩 | 去重、摘要、裁剪，只保留关键证据 |
| 引用 | 让答案能回查到来源 |

## RAG 不是万能的

RAG 系统常见失败包括：

- 检索不到关键证据。
- 检索到了但排序靠后。
- 分块破坏了语义完整性。
- 上下文太长导致关键证据被忽略。
- 多个证据冲突但没有处理。
- 模型没有严格基于证据回答。

因此 RAG 的工程重点不是“接一个向量库”，而是召回、排序、上下文构造、生成约束和质量评估。
