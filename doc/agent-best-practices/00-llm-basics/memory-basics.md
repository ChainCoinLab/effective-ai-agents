# 00.9 记忆基础

[返回全局摘要](../README.md) · [返回本组：AI 工程基础知识与原理](README.md)

大模型本身没有可靠的持续记忆。所谓“记住了”，通常是应用把历史消息、用户偏好、长期事实或工具结果保存下来，并在后续请求中重新注入上下文。

## 记忆解决什么问题

记忆解决的是跨轮次、跨会话的连续性问题：

- 用户偏好需要长期保留。
- 项目背景需要多次复用。
- 已确认事实不应反复询问。
- 长任务中间结果需要持续保存。
- Agent 需要知道之前做过什么。

## 多轮对话为什么看起来有记忆

聊天产品里的连续对话，通常不是模型自己在“脑子里记住了上一轮”，而是应用系统在下一次请求时，把历史消息、系统指令、外部记忆、工具结果和当前用户输入重新组装成上下文，再传给模型。

```text
第 1 轮：
system + user_1 -> model -> assistant_1

第 2 轮：
system + user_1 + assistant_1 + user_2 -> model -> assistant_2

第 3 轮：
system + user_1 + assistant_1 + user_2 + assistant_2 + user_3 -> model -> assistant_3
```

所以更准确的说法是：多轮对话依赖上下文重放，长期连续性依赖应用层的记忆和状态系统。

## 记忆类型

| 类型 | 内容 | 示例 |
| --- | --- | --- |
| 短期上下文 | 当前会话里的近期消息 | 最近几轮对话、当前任务说明 |
| 长期记忆 | 稳定事实或偏好 | 用户偏好的语言、项目技术栈 |
| 工作记忆 | 当前任务临时信息 | 待处理文件、当前计划、临时结论 |
| 外部知识 | 可检索材料 | 文档库、知识库、数据库 |

## 记忆不是状态

记忆偏事实和偏好，状态偏流程进度。不要把审批状态、付款状态、任务是否完成这类信息只放进自然语言记忆里。这些应该由确定性系统管理。

## 工程原则

- 只写入稳定、明确、用户授权的信息。
- 记忆要有来源、时间戳和适用范围。
- 用户纠正后要能更新和删除。
- 敏感信息默认不进入长期记忆。
- 读取记忆时要按任务相关性筛选，而不是全部注入上下文。
