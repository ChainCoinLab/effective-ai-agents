# 架构设计

[返回全局摘要](../README.md)

架构设计模块关注真实业务系统里的高可用、高并发、高安全、可观测、可扩展和可恢复。它不是为了堆组件，而是训练一种判断方式：先识别业务目标、状态边界和系统瓶颈，再决定模块怎么拆、怎么通信、怎么校验、怎么恢复。

本模块先从永续合约订单簿 L1 开始：订单意图、mempool、共识最终性、价格快照、多交易队列、撮合、保证金、资金费率、清算、索引器和验证测试。核心问题是：哪些状态必须确定性重放，哪些链路可以异步派生，排序、公平性、风控和最终性分别由哪个模块负责，以及如何用测试证明方案有效。

## 架构判断

架构设计不能从中间件清单开始，而要从业务不变量和状态 owner 开始：

```text
业务目标
-> 正确性不变量
-> 状态 owner
-> 同步热路径
-> 异步派生链路
-> 通信事件
-> 校验与回放
-> 压测和故障演练
```

只有能解释“为什么这样拆模块、谁拥有状态、模块之间怎么通信、怎么校验正确性、瓶颈证据是什么、失败后怎么恢复”的方案，才是可落地的架构设计。
