# 从零实现 Skill

[返回源码实现](../README.md)

这个教程线用于补齐 Skill 的源码实现。Skill 不是一句角色设定，也不是一段泛泛提示词，而是可复用的任务能力包：它应该包含触发条件、适用边界、执行步骤、工具依赖、输出标准和验证方法。

## 最终目标

学完这个专题后，应该能把一个稳定任务从自然语言经验沉淀成可加载、可路由、可验证的 Skill：

```text
任务 SOP
  ↓
Skill 元数据
  ↓
触发条件和排除条件
  ↓
执行步骤和工具依赖
  ↓
输出结构和质量标准
  ↓
路由、加载、执行、验证
```

## 计划中的学习路径

| 顺序 | 学习点 | 本节只解决什么问题 |
| --- | --- | --- |
| 01 | 定义 Skill 元数据 | 描述 `name`、`description`、`trigger`、`do_not_use_when` 和版本 |
| 02 | 把 SOP 转成执行步骤 | 把经验流程拆成模型可执行的 checklist |
| 03 | 声明工具依赖 | 标明 Skill 需要哪些工具、权限和输入 |
| 04 | 设计输出结构 | 用 JSON schema 或固定 Markdown 结构约束结果 |
| 05 | 实现 Skill 路由 | 根据任务意图选择候选 Skill |
| 06 | 动态组装 Skill 上下文 | 只加载当前任务需要的 Skill 片段 |
| 07 | 验证 Skill 执行质量 | 记录命中原因、执行轨迹、输出校验和失败样例 |

## 和 Agent / MCP 的关系

- Agent 负责接收目标、规划任务和调度执行。
- MCP 负责把外部工具、资源和提示模板标准化暴露出来。
- Skill 负责沉淀任务方法、执行步骤、工具使用方式和质量标准。

大量 Skill 共存时，需要进一步考虑注册、路由、检索、冲突处理、动态组装和回归测试。可以继续阅读 [大量 Skill 共存解决方案](../../04-tools-agents/large-scale-skill-engineering.md)，再回到 [工具调用、MCP 与多 Agent](../../04-tools-agents/README.md) 看 Skill、记忆、状态、动态上下文和 trace 如何串成完整运行链路。
