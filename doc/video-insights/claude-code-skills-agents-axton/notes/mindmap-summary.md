# 《Claude Code: 从零搭建你的 AI 工作团队》提炼版

## 中心思想

用 Claude Code 搭建 AI 工作团队的关键，不是让 AI 自由发挥，而是先把人的工作流程、判断标准和协作边界沉淀成 `Skills`，再用有明确职责的 `Agents` 调用这些 Skills 执行任务。  

核心公式：

```text
人的经验与流程 -> Skill 标准操作手册 -> Agent 角色执行 -> 可复用的 AI 工作系统
```

## 主要论点、论据、论证重点

| 论点 | 论据 | 论证重点 |
| --- | --- | --- |
| AI 工作团队需要流程化设计 | 作者演示从内容审查到发布的完整工作流 | AI 不只是聊天工具，而是可以被组织成工作系统 |
| Skill 是 AI 的操作手册 | `content-review` Skill 明确审查标准、模型分工和输出格式 | Skill 让隐性的人工经验变成 AI 可执行规则 |
| Agent 是负责执行的角色 | `publisher` Agent 串联审查和发布两个 Skills | Agent 的价值是承担职责和调度流程 |
| 应该先做 Skill，再做 Agent | 作者用创业公司类比：先跑通业务流程，再招人执行 | 没有流程的 Agent 会不可控 |
| 多模型交叉审查比单模型更可靠 | Claude 发现结构问题，Gemini 发现事实和表达问题 | 不同模型有不同盲区，交叉检查能提高覆盖面 |
| MCP 让 AI 能连接真实工具 | `wechat-publish` 通过 Make MCP 发布到公众号草稿箱 | 真正的自动化需要工具调用，不只是文本生成 |
| Agent 不一定都要装备 Skill | `demo-social-voice` 只靠系统提示词生成推文 | 简单任务不必过度工程化 |
| 系统可以持续扩展 | 作者提到 12 个 Agent，覆盖信息筛选、策划、视频、设计、发布 | Skills + Agents 是一种可扩展架构 |

## 视频重点讲了什么

### 重点 1: 从单次对话转向可复用系统

作者不是在讲“如何问 Claude 一个好问题”，而是在讲如何把 Claude Code 变成长期可复用的工作系统。关键是项目里要有上下文、规范、模板、Skills 和 Agents。

### 重点 2: Skill 承载流程和标准

视频反复强调，把脑子里的判断标准写下来非常重要。比如内容审查不是一句“帮我看看这篇文章”，而是明确规定审查维度、模型分工、输出格式和报告结构。

### 重点 3: Agent 承担角色和调度

Agent 不是泛泛的“万能助手”，而是有明确职责的成员。例如 `publisher` 只负责从定稿到发布，先审查，再发布；`demo-social-voice` 只负责把长内容变成社交短内容。

### 重点 4: 复杂任务要串联多个 Skills

发布一篇文章不是单个动作，而是一条流水线：

```text
文章输入 -> 内容审查 -> 判断是否通过 -> 生成发布元数据 -> 调用发布工具 -> 返回结果
```

这个流程由 `publisher` Agent 串联 `content-review` 和 `wechat-publish` 两个 Skills 完成。

### 重点 5: 真正自动化必须连接外部工具

只会生成文本的 AI 仍然停留在建议层面。通过 MCP 接入 Make 后，Claude Code 可以触发微信公众号发布工作流，把 AI 输出推进到真实业务动作。

## 适合复用的结论

1. 不要先问“我要创建几个 Agent”，而要先问“我的工作流有哪些稳定步骤”。
2. 能写成 SOP 的流程，就应该先做成 Skill。
3. 需要长期承担职责、串联流程的角色，再做成 Agent。
4. 涉及外部系统的动作，用 MCP/API 封装成 Skill。
5. 涉及发布、删除、付款等高风险动作，要保留人工确认。
6. 简单改写类任务可以只用轻量 Agent，不需要强行做 Skill。

## 最终提炼

这条视频真正讲的是一种 AI 自动化架构方法：

```text
上下文让 AI 理解你是谁；
Skill 让 AI 知道怎么做；
Agent 让 AI 知道什么时候由谁来做；
MCP 让 AI 能把事情做到外部系统里。
```

如果只记一句话，就是：

```text
先把流程写成 Skill，再让 Agent 按流程执行。
```
