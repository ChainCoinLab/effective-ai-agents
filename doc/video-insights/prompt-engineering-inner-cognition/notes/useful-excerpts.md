# 面试官：Prompt Engineering能真正操控大模型的内在认知吗？有用摘录

## 可复用观点

- 大模型没有人类意义上的信念、三观或主观认知；在工程语境里，“认知”应理解为参数分布、权重结构和长期行为倾向。
- Prompt 的本质是改变当前上下文下下一 token 的条件概率，它能激发已有能力，但不能把新知识写入模型参数。
- RAG 更像给模型一本参考书，让模型开卷回答；它解决知识访问问题，不等于模型真正学会了这些知识。
- RePE / 表征工程是在推理阶段干预隐层激活，比 Prompt 更深入，但仍然不是长期记忆修改。
- 真正改变模型长期认知，需要通过 SFT、继续预训练等方式更新权重参数。

## 可复用方法

回答类似面试题时，不要急着选“能”或“不能”，先拆技术层级：

1. 当前上下文层：Prompt。
2. 外部知识层：RAG。
3. 推理表征层：RePE。
4. 参数学习层：SFT / 继续预训练。

然后说明每层解决什么问题、是否改参数、适合什么工程场景。

## 可复用面试回答

> 严格来说，Prompt Engineering 不能真正操控大模型的内在认知。因为如果把认知定义为模型的参数分布、权重结构和长期行为倾向，Prompt 并不会触发梯度更新，也不会修改权重。它只是通过上下文改变注意力分布和下一 token 的条件概率，激发模型已有知识或行为模式。
>
> 工程上要区分几层：激发已有能力用 Prompt；引入外部新知识用 RAG；推理时干预行为可以关注 RePE；如果要长期改变模型行为或注入垂直领域常识，就要用 SFT 或继续预训练。面试里关键不是简单说能不能，而是说清楚工作记忆和长期记忆的边界。

## 值得保留的表达

- Prompt 像探照灯：照亮预训练中已有的一小块知识区域。
- RAG 像开卷考试：模型会参考资料，但资料没有写进模型脑子里。
- 参数矩阵才是模型的长期记忆。

## 暂不采纳的内容

- “操控认知”这个说法本身容易拟人化，正式表达时建议改成“改变长期行为倾向”或“改写参数化知识/能力”。
