# 面试官：Prompt Engineering能真正操控大模型的内在认知吗？思维导图提炼

## 中心思想

Prompt Engineering 是上下文层面的行为引导，不是参数层面的认知重塑。要把这道题答好，必须区分“当前输出被引导”和“长期参数被改变”。

## 思维导图

```text
Prompt Engineering 能操控大模型内在认知吗？
├─ 先定义认知
│  ├─ 不是人类信念、三观或意识
│  └─ 是参数分布、权重结构和长期行为倾向
├─ Prompt 的边界
│  ├─ 改变当前上下文里的条件概率
│  ├─ 依赖 KV Cache / 工作记忆
│  └─ 不改参数，不写入新知识
├─ RAG 的边界
│  ├─ 把外部资料放进上下文
│  ├─ 解决新知识访问问题
│  └─ 像开卷考试，不是模型真正学会
├─ RePE 的定位
│  ├─ 干预推理过程中的隐层表示
│  ├─ 比 Prompt 更接近内部处理过程
│  └─ 不通过反向传播更新权重
└─ 真正改变认知
   ├─ SFT / 继续预训练
   ├─ 梯度下降 + 反向传播
   └─ 修改权重参数，也就是长期记忆
```

## 论点、论据、论证

| 论点 | 论据 | 论证重点 | 我的判断 |
| --- | --- | --- | --- |
| Prompt 不能真正改认知 | 新对话后上下文和 KV Cache 清空，参数不变 | Prompt 是瞬时上下文引导 | 这是核心答案 |
| RAG 也不改认知 | 检索内容只是被填入 Prompt | RAG 是外部知识参考，不是内化学习 | 面试中要避免把 RAG 说成“模型学会了” |
| RePE 更深但仍有限 | 干预推理时的中间激活 | 它影响处理过程，但不更新长期参数 | 可作为加分项 |
| SFT/预训练才改长期行为 | 通过梯度下降和反向传播修改权重 | 参数矩阵承载长期记忆 | 工程选型时要明确成本和目标 |
