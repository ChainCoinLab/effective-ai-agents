# 面试官：Prompt Engineering能真正操控大模型的内在认知吗？体验总结

## 我认可的部分

- 这个视频抓住了面试题的关键：区分工作记忆和长期记忆，而不是泛泛讨论 Prompt 是否有效。
- 把 Prompt、RAG、RePE、SFT 放在同一条“干预深度”轴线上比较，适合用作面试回答结构。
- 对 Prompt 和 RAG 的边界讲得比较清楚：它们都能改变输出表现，但都不等于参数级学习。

## 我存疑的部分

- 视频把“认知”基本等同于参数分布，这在面试中有用，但严格学术语境下还可以更谨慎，避免过度简化。
- RePE 示例用了“诚实向量”这类表达，便于理解，但实际工程可控性、泛化性和稳定性需要进一步验证。

## 可以马上实践的动作

1. 把 `notes/useful-excerpts.md` 中的“可复用面试回答”整理进大模型面试题库。
2. 在 Prompt/RAG/微调选型文档里增加一列：是否修改参数、是否改变长期行为。
3. 面试时遇到“Prompt 能不能控制模型”类问题，先定义术语，再分层回答。

## 后续要验证的问题

- RePE 在真实生产系统里的可控性、可解释性和安全边界如何？
- SFT 和 RAG 在垂直领域知识注入上，如何按成本、更新频率和可追溯性做选型？
- “认知”是否应拆成知识记忆、推理策略、偏好对齐、行为风格等多个维度讨论？

## 我的结论

这个视频最有价值的是提供了一个面试回答框架：Prompt 不是没用，而是它只作用于当前上下文；RAG 是外部知识参考；RePE 是推理时内部干预；参数更新才是长期认知/行为模式改变的关键。
